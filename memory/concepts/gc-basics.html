Concept 19 of 29 · ♻️ Garbage collector

The cleaner who keeps only what is on the guest list.

How the GC decides what is garbage: start at the roots, follow every reference, and reclaim whatever you never reached — then slide the survivors together.

❓ "How does the .NET garbage collector decide which objects to free?"
👁 See it first
🎯 An object is garbage when no chain of references leads to it from a root.
🌍 In real life

🎉 A party with a guest list. The cleaner starts with the people at the door (roots) and asks “who did you bring?”, then “who did they bring?”. Everyone found that way stays.

Anyone who was never connected to the list — even two strangers chatting in a corner who only know each other — gets shown out. The cleaner never needs to ask the strangers anything.

⚠️ Honest note

This lab shows the idea of marking and compacting. Roots, the mark → relocate → compact phases and the triggers are documented by Microsoft. The object layout (header, type pointer, fields) is the classic runtime model, and the layout, colours and addresses in the pictures are a teaching picture. The real collector has many optimisations and settings (workstation/server, concurrent); the exact algorithms inside are not claimed.

🧪 Tiny code
void Run()
{
    var a = new Order();       // a (a stack root) → Order: reachable, kept
    a = null;                  // no root reaches that Order now: garbage
}                              // when Run returns, its locals are no longer roots either

static Order Cache = new();    // a static root: everything it references is kept

The GC decides by reachability, not by “scope ended” and not by a reference counter.

♻️ Who clears this memory?

The GC, not at a time you choose. Becoming unreachable only makes an object eligible; the memory is reclaimed during some later collection, when the GC decides to run.

🎯 Check yourself
▾ Two objects that point only at each other can never be freed.

❌ Wrong. If no root reaches them, both are garbage — a cycle does not keep them alive.

▾ A static field is a GC root.

✅ Right. Yes — whatever it references stays alive.

▾ Setting a variable to null immediately frees the object.

❌ Wrong. It only removes one reference; the memory is reclaimed during a later GC, if nothing else reaches the object.

🔥 Interview recall
  • GC finds live objects by following references from roots (stack locals, statics, …).
  • Unreached objects are garbage — cycles included.
  • Phases: mark → relocate (rewrite references) → compact (slide); compaction only when worthwhile.
🎤 Say this in an interview
“The GC traces reachability from roots such as stack locals and static fields; anything it cannot reach is garbage, including reference cycles. It then updates references and compacts the survivors.”
⚠️ Common trap

Thinking = null or leaving a scope frees memory now. Reclaiming is the GC’s decision and happens later.
