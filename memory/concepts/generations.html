Concept 20 of 29 · ♻️ Garbage collector

The nursery, the school and the retirement home.

Why the .NET heap has three generations, how objects move from G0 to G1 to G2, and why most collections are quick.

❓ "Explain generations 0, 1 and 2 in the .NET garbage collector."
👁 See it first
🎯 Most objects die young, so the GC checks the young generation often and cheaply, and the old generation rarely.
🌍 In real life

🏫 Nursery → school → retirement home. Newborns (new objects) are checked every day: most are only visitors who leave quickly. Those who stay a while move to school; those who stay for years move to the retirement home, which the inspector visits only occasionally.

It would be wasteful to search the whole city (the whole heap) every day when the visitors are all in the nursery.

📋 The three generations
GenerationHoldsCollectedCost of a collection
🌱 Gen 0new, short-lived objects (temporary values, request data)most oftensmall area → very quick
🎓 Gen 1survivors of one gen 0 collectionsometimes — a buffer between short and long-livedsmall
🏛️ Gen 2long-lived objects (caches, app-wide data) and the large object heaprarelywhole heap → slowest
🧾 Rules to remember
RuleMeaning
Collecting generation N also collects all younger generationsa gen 1 GC includes gen 0; a gen 2 GC is a full GC
Survivors are promoted one stepgen 0 → gen 1 → gen 2; gen 2 survivors stay in gen 2
A promoted object is not copied away from the programreferences are updated when objects move (page 19)
🔎 Peek at a generation (diagnostics only)

GC.GetGeneration(obj) tells you which generation an object is in right now. It is a handy way to see promotion while learning, but do not build program logic on it — the GC may collect or promote at any time.

🧪 Tiny code
var o = new object();
Console.WriteLine(GC.GetGeneration(o));   // 0 — new objects start in generation 0
GC.Collect();                             // for the demo only! avoid in real code
Console.WriteLine(GC.GetGeneration(o));   // typically 1 — it survived, so it was promoted

The printed numbers are typical, not guaranteed. Never call GC.Collect() in production code just to “help”.

♻️ Who clears this memory?

The GC, one generation at a time. Short-lived objects are freed in cheap gen 0 collections; long-lived ones only in the occasional gen 2 collection. That is why creating a lot of short-lived objects is cheap, and creating objects that survive a while and then die is the costly pattern (they get promoted, then must wait for a bigger collection).

🎯 Check yourself
▾ A gen 2 collection only looks at gen 2 objects.

❌ Wrong. It collects all generations (0, 1 and 2).

▾ New objects start in generation 0.

✅ Right. Yes (large objects are the exception — next page).

▾ An object that survives a gen 0 collection goes straight to gen 2.

❌ Wrong. One step at a time: gen 0 → gen 1 → gen 2.

🔥 Interview recall
  • Gen 0 = new, gen 1 = buffer, gen 2 = long-lived.
  • Survive a collection → promoted one generation.
  • Collecting generation N also collects younger generations; gen 2 collection = full GC.
🎤 Say this in an interview
“The managed heap is generational: new objects go in gen 0, survivors are promoted to gen 1 then gen 2. Because most objects die young, gen 0 collections are frequent and cheap, while gen 2 collections are rare and expensive and examine every generation.”
⚠️ Common trap

Objects that live “just long enough” to be promoted — then die in gen 2 — force expensive collections. Avoid holding temporary data in long-lived places.
