Concept 12 of 29 · 🧬 Objects & types

Building a house: land, frame, then the rooms.

The exact order inside new: reserve memory, default values, field initializers, constructor body — plus objects holding objects and arrays of objects.

❓ "What is the order of events when an object is created in C#?"
👁 See it first
🎯 new = reserve memory → defaults → field initializers → constructor body → hand back the reference.
🌍 In real life

🏠 Building a house: first the land is marked out (memory reserved, empty), then the frame goes up (initializers), then the finishing touches (constructor), and finally you get the key (the reference).

You can never enter a house before it has land — an object always has all of its memory before any of your code runs inside it.

🪆 An object that holds another object
🧺 An array of objects
🧪 Tiny code
class Customer { }
class Order
{
    int qty = 1;                         // 2) field initializer
    string note;                         // 1) starts as null
    Customer cust = new Customer();      // 2) builds a second heap object
    public Order() { note = "new"; }     // 3) constructor body, after the initializers
}

var o = new Order();                      // 4) o holds the reference
var a = new Person[3];                    // 3 null slots, no Person yet

Field initializers run before the constructor body. (With inheritance there is one more rule — next pages.)

♻️ Who clears this memory?

The garbage collector, at a later GC — not the moment the variable is cleared. An object graph is freed as a whole: when nothing reachable points to the Order, the Order and the Customer it alone referenced are both unreachable and can both be freed. The GC follows references, so you never “delete” the inner objects by hand.

🎯 Check yourself
▾ The constructor body runs before field initializers.

❌ Wrong. Field initializers run first, then the constructor body.

▾ new Person[3] creates three Person objects.

❌ Wrong. It creates one array with three null slots.

▾ A field of class type holds the address of another heap object.

✅ Right. Yes — that is how objects link together.

🔥 Interview recall
  • Space is reserved with every field at its default value; then field initializers; then the constructor body.
  • Every heap object has a header and a type pointer; a field of class type holds a reference to another object.
  • new T[n] for a class T makes n empty slots, not n objects.
🎤 Say this in an interview
“new allocates the object with default field values, runs field initializers, then the constructor body, and returns a reference. Objects that hold other objects just store references to them on the heap.”
⚠️ Common trap

Using an array element without creating the object: a[1].Name throws a NullReferenceException because slot 1 is still null. (Contrast: new int[3] holds three zeros directly in the array, because int is a value type.)
