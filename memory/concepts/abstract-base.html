Concept 14 of 29 · 🧬 Objects & types

A blueprint nobody can live in — only the houses built from it.

Why you can never create an abstract class by itself, what memory a child object really gets (one header, one type pointer, all the fields), and how one base type serves many kinds of objects.

❓ "How is memory allocated for an abstract class and its derived classes?"
👁 See it first
🎯 An abstract class is never created alone; its memory exists only as the base fields inside an object of a child class.
🌍 In real life

🏗️ An architect’s blueprint for “a payment”: it lists what every payment must have (an amount) and must do (pay), but nobody can live in a blueprint.

You can only live in a house built from it — a card payment, a UPI payment. Each house contains everything the blueprint demanded, plus its own rooms.

🧪 Tiny code
abstract class Payment
{
    public decimal Amount;
    protected Payment() { Amount = 100; }     // runs, but only while building a child
    public abstract void Pay();               // no body: children must supply it
}
class CardPayment : Payment { public override void Pay() { /* card */ } }
class UpiPayment  : Payment { public override void Pay() { /* UPI  */ } }

// var x = new Payment();                     // ❌ cannot create an abstract class
Payment p1 = new CardPayment();               // ✅ typed as the base
Payment p2 = new UpiPayment();

The variable type may be abstract; the object that it points to is always a concrete child.

♻️ Who clears this memory?

The GC frees the whole child object (base fields included) and, if nothing else refers to it, its string, once nothing references the object — not at the end of the method, but at some later collection. Because abstract classes have no objects of their own, there is nothing separate to clean. The MethodTables belong to the types and stay.

🎯 Check yourself
▾ An abstract class can be created with new if it has a constructor.

❌ Wrong. Never. The constructor is only used by child classes.

▾ A Payment-typed variable can point to a CardPayment object.

✅ Right. Yes — and the object stays a CardPayment.

▾ The abstract base’s fields take up memory even though no one can create it alone.

✅ Right. Yes — inside every child object.

🔥 Interview recall
  • new on an abstract class is a compile error (a build-time rule, nothing is allocated).
  • A child object is ONE object: one header, one type pointer, the fields of base and child. The base constructor body runs before the child’s constructor body.
  • Variable type can be abstract; the object is a concrete child, and its type pointer decides which method runs.
🎤 Say this in an interview
“An abstract class cannot be instantiated; its fields exist only as part of an instance of a derived class, which is one heap object with one header and one type pointer. The base constructor runs as part of constructing that instance. A variable can be typed as the abstract class and refer to any concrete subclass; virtual calls go through the object’s type pointer.”
⚠️ Common trap

Thinking an abstract class “costs nothing”. Every child object carries its fields — a bloated base class makes every object bigger.
