Concept 18 of 29 · 🧬 Objects & types

A contact card — and a note that carries a backpack.

What a delegate is in memory (a small heap object: “call this method on that object”), what a lambda does when it uses local variables (the compiler moves them into a heap closure), and why that can keep memory alive.

❓ "What happens in memory when you create a delegate or a lambda that captures a variable?"
👁 See it first
🎯 A delegate is a heap object holding a method plus the object to call it on; a capturing lambda adds a closure object that holds the variables it uses.
🌍 In real life

📇 A contact card with a name and a phone line: “call Asha’s SayHi line”. Anyone holding the card can make that call later. The card keeps Asha’s details from being thrown away while it exists.

🎒 A capturing lambda is a note that says “do this” and comes with a backpack of the things it needs (the captured variables). The backpack must stay around as long as the note does.

🎒 A lambda that captures a variable: the closure

⚡ Performance lens — think like this

A capturing lambda created inside a hot loop or on every request allocates a closure and a delegate each time. Move it out of the loop, or pass the data as parameters instead of capturing.

Use a static lambda (C# 9+) where you do not need captures: the compiler stops you from capturing by accident.

Event subscriptions are delegates (page page 23): += stores a delegate whose target is the subscriber — that is how a long-lived publisher keeps a short-lived subscriber alive. Unsubscribe with -=.

A delegate holds a strong reference to its target. If a lambda captures a big object “just to read one field”, it keeps the whole object alive.

🔬 Honest notes

Microsoft documents that captured variables live at least as long as the delegate that uses them, that the compiler stores them in a heap-allocated closure object, and that a static lambda cannot capture. The exact class names and layout the compiler generates (“display class”) are implementation details and can change; the lab draws the idea.

🧪 Tiny code
var person = new Person("Asha");
Action greet = person.SayHi;            // Delegate object: target = person, method = SayHi
greet();                                // runs person.SayHi()

int count = 0;
Action inc = () => count++;             // captures count → closure object on the heap
inc(); inc();                           // count == 2, even after this method has returned

Func<int, int> twice = static x => x * 2;   // static lambda: cannot capture, no closure

The delegate (and any closure) is an ordinary heap object. Keep it reachable and its target and captured variables stay alive.

♻️ Who clears this memory?

The GC, once nothing references the delegate. Then the delegate, its closure and (if nothing else references them) its target become garbage together. So the way to release a captured object is to drop the delegate (unsubscribe, clear the field, let it go out of scope).

🎯 Check yourself
▾ A delegate stores only the method, not the object it will be called on.

❌ Wrong. It stores both: the target object (for instance methods) and the method.

▾ A lambda that uses a local variable makes that variable live on the heap inside a closure.

✅ Right. Yes — it is captured into a closure object.

▾ A static lambda can capture local variables.

❌ Wrong. It cannot — that is the point of static.

🔥 Interview recall
  • Delegate = heap object holding target + method.
  • Capturing lambda = delegate + closure object holding the captured variables.
  • Captured variables live as long as the delegate; long-lived delegates keep them alive.
🎤 Say this in an interview
“A delegate is a heap object holding a target and a method. A lambda that captures locals gets a compiler-generated closure object on the heap, so those variables live as long as the delegate does — which is why long-lived delegates, like event handlers, can keep objects alive.”
⚠️ Common trap

Storing a lambda in a static field or long-lived event that captures a large object (a page, a request, a service) — the closure keeps it alive forever.
