Concept 13 of 29 · 🧬 Objects & types

A nesting doll: creating a Dog also builds the Animal inside it.

What new Dog() allocates when Dog inherits from Animal: one object with a type pointer and both sets of fields, the constructor order, and what a base-type variable can see.

❓ "When you create a subclass object, what happens to the base class memory?"
👁 See it first
🎯 A subclass object is ONE object: header, type pointer, and the base-class fields plus the subclass fields.
🌍 In real life

🪆 A nesting doll: one doll, but you cannot make the inner layer without the outer shell around it — and you cannot make the outer layer without building the inner part first.

A Dog is an Animal: it has everything an Animal has plus its own extras. So memory for both is reserved together, in one block.

👁️ A base variable pointing at a child object
📋 The two orders to remember
WhatOrderWhy it helps
Field initializersderived class first, then basea documented C# rule
Constructor bodiesbase class first, then derivedthe parent part is ready before the child uses it
Memoryallocated once, for the whole objectthere is just one object and one type pointer
🧪 Tiny code
class Animal
{
    string Name = "?";                     // runs 3rd (base initializer)
    public Animal() { Name = "Rex"; }      // runs 4th (base constructor)
}
class Dog : Animal
{
    string Breed = "Lab";                  // runs 2nd (derived initializer)
    public Dog() { Breed = "Pug"; }        // runs 5th (derived constructor)
}

Animal a = new Dog();     // ONE Dog object on the heap
// a.Breed;               // ❌ not visible through an Animal variable
var dog = (Dog)a;         // ✅ same object, bigger view

Never call an overridable method from a constructor: the object’s type pointer already says Dog, so the override runs while the Dog fields may still be at their defaults (see the trap).

♻️ Who clears this memory?

The garbage collector frees the whole Dog object at once — base and derived fields together — when nothing references it (both a and dog must be gone). There is no way to free just the Animal part.

Replaced strings ("?", "Lab") are separate heap objects: once unreferenced they are freed by a later GC, not at the moment of assignment.

🎯 Check yourself
▾ new Dog() creates a Dog object and a separate Animal object.

❌ Wrong. One object only. The Animal fields are inside it.

▾ Constructor bodies run base → derived.

✅ Right. Yes, the base constructor completes first.

▾ Animal a = new Dog(); turns the object into an Animal.

❌ Wrong. The object stays a Dog (its type pointer says Dog); only the variable’s view is Animal.

▾ (Dog)a makes a copy of the object.

❌ Wrong. It copies the reference only: two variables, one object.

🔥 Interview recall
  • One object holds base + derived fields, plus a type pointer that says Dog.
  • Field initializers: derived → base. Constructors: base → derived.
  • A base variable can point at a derived object but only sees base members; a cast copies the reference, not the object.
🎤 Say this in an interview
“A derived-class instance is a single heap object containing the base fields and the derived fields, with a type pointer to its real type. Field initializers run derived first then base, and constructors run base first then derived. A base-typed variable references the same object but only exposes base members; a cast checks the real type and copies the reference.”
⚠️ Common trap

Calling a virtual method from a base constructor. The object’s type pointer already says Dog, so the derived override runs while the derived constructor body has not run yet (derived fields are still null or default, or only initializers have run) — a classic bug.
