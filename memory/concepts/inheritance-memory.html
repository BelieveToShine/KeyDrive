A nesting doll: creating a Dog also builds the Animal inside it.

What new Dog() allocates when Dog inherits from Animal: one object with both layers, the constructor order, and what a base-type variable can see.

❓ "When you create a subclass object, what happens to the base class memory?"
👁 See it first
🎯 A subclass object is ONE object that contains the base-class fields and the subclass fields.
🌍 In real life

🪆 A nesting doll: one doll, but you cannot make the inner layer without the outer shell around it — and you cannot make the outer layer without building the inner part first.

A Dog is an Animal: it has everything an Animal has plus its own extras. So memory for both is reserved together, in one block.

👁️ A base variable pointing at a child object
📋 The two orders to remember
WhatOrderWhy it helps
Field initializersderived class first, then basea documented C# rule
Constructor bodiesbase class first, then derivedthe parent part is ready before the child uses it
Memoryallocated once, for the whole objectthere is just one object and one address
🧪 Tiny code
class Animal
{
    string Name = "?";                     // runs 3rd (base initializer)
    public Animal() { Name = "Rex"; }      // runs 4th (base constructor)
}
class Dog : Animal
{
    string Breed = "Lab";                  // runs 2nd (derived initializer)
    public Dog() { Breed = "Pug"; }        // runs 5th (derived constructor)
}

Animal a = new Dog();     // ONE Dog object on the heap
// a.Breed;               // ❌ not visible through an Animal variable
var dog = (Dog)a;         // ✅ same object, bigger view

Never call an overridable method from a constructor: the child part may not be initialised yet (see the trap).

♻️ Who clears this memory?

The garbage collector frees the whole Dog object at once — base and derived layers together — when nothing references it. There is no way to free just the Animal part.

🎯 Check yourself
▾ new Dog() creates a Dog object and a separate Animal object.

❌ Wrong. One object only. The Animal part is the first layer inside it.

▾ Constructor bodies run base → derived.

✅ Right. Yes, the base constructor completes first.

▾ Animal a = new Dog(); turns the object into an Animal.

❌ Wrong. The object stays a Dog; only the variable’s view is Animal.

🔥 Interview recall
  • One object holds base + derived fields.
  • Field initializers: derived → base. Constructors: base → derived.
  • A base variable can point at a derived object but only sees base members.
🎤 Say this in an interview
“A derived-class instance is a single heap object containing the base fields and the derived fields. Field initializers run derived first then base, and constructors run base first then derived. A base-typed variable references the same object but only exposes base members.”
⚠️ Common trap

Calling a virtual method from a base constructor. It runs the derived override while the derived fields are still at their defaults (or only initializers have run) — a classic bug.
