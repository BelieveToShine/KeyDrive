Concept 4 of 29 · 📚 Stack & heap

The warehouse and the claim ticket.

What new does step by step: it finds room on the managed heap, prepares the object and hands back an address you keep on the stack.

❓ "What happens in memory when you write new Person("Asha")?"
👁 See it first
🎯 new builds the object on the heap and gives you back its address.
🌍 In real life

🏬 A warehouse: you hand over a parcel, they find shelf space, put it there and give you a claim ticket with its shelf number. You keep the ticket (the reference); the parcel stays in the warehouse (the heap).

If you lose every copy of the ticket, nobody can fetch the parcel — the warehouse (the garbage collector) can eventually clear the shelf.

🔤 Arrays: numbers inside, or addresses inside
🔬 Hidden bookkeeping

Every heap object starts with a hidden header and a type pointer to its type’s MethodTable (one per type, shared by all its objects), then your fields. A reference points at the type-pointer word. This is how the runtime knows which methods to call — see page 16. Exact sizes and field order differ between runtime versions, so this lab never quotes byte sizes; the pictures are a teaching picture.

🧪 Tiny code
class Person {
    public string Name; public int Age;
    public Person(string n) { Name = n; }
}

var p = new Person("Asha");  // 1) room  2) zeroed: Name=null, Age=0
                             // 3) ctor: Name = reference to the string "Asha"
                             // 4) address stored in p
var q = p;                   // copies the address: still ONE Person
p = null;                    // q still reaches it, so it stays alive

Fields get default values (0, false, null) before your constructor code runs. The string "Asha" is its own object; Name only holds its address.

♻️ Who clears this memory?

The garbage collector, later, once no variable (and nothing else reachable) holds the address. Setting p = null; only removes one ticket; the object is freed only if no other reference remains. You never free heap memory by hand in C#.

🎯 Check yourself
▾ new Person() returns the object itself.

❌ Wrong. It returns a reference (address) to the object.

▾ Fields of a new object start at default values (0, null, false).

✅ Right. Yes, before the constructor body runs.

▾ Setting p = null immediately frees the object.

❌ Wrong. It drops one reference; the GC frees the object later, if nothing else points to it.

▾ In a Person object, the Name characters are stored inside the Person.

❌ Wrong. No. Name holds the address of a separate string object.

🔥 Interview recall
  • new: reserve room on the heap → default values → constructor → return address.
  • A heap object = header + type pointer + fields; reference fields point to other objects.
  • The variable holds the address; you do not free heap memory yourself — the GC does.
🎤 Say this in an interview
“new allocates the object on the managed heap, zero-initialises its fields, runs the constructor and returns a reference, which the variable holds. Reference fields such as a string point to separate heap objects. The garbage collector reclaims them when nothing reachable references them.”
⚠️ Common trap

Thinking = null “deletes” the object. It only removes that variable’s reference; the memory is cleared by a later GC, if nothing else reaches it.
