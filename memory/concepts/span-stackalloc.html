Concept 28 of 29 · ⚙️ Tuning & judgement

A window onto the shelf instead of copying the shelf.

The best way to make the GC’s life easy is to allocate less: stack space for tiny buffers, Span<T> to look without copying, and pools to reuse arrays.

❓ "How can you reduce allocations and GC pressure in C#?"
👁 See it first
🎯 Allocate less: stack space for tiny buffers, Span to look without copying, pools to reuse big arrays.
🌍 In real life

📚 A library has a shelf of books. To copy a chapter you photocopy it (a new heap object). With a Span you just hold a transparent window over the page — no copy. A pool is the library lending you a book and taking it back, instead of printing a new one each time.

♻️ ArrayPool: borrow, use, give back
🪟 Span: look, don’t copy

🧪 Tiny code
// small buffer on the stack, big one from the pool — standard pattern
const int Threshold = 1024;
byte[]? rented = null;
Span<byte> buffer = length <= Threshold
    ? stackalloc byte[length]
    : (rented = ArrayPool<byte>.Shared.Rent(length));
try
{
    Process(buffer[..length]);          // a slice: no copy
}
finally
{
    if (rented != null) ArrayPool<byte>.Shared.Return(rented);
}

ReadOnlySpan<char> part = "Hello!".AsSpan(1, 3);   // "ell" — no new string

This follows Microsoft’s documented pattern: stack-allocate below a threshold, otherwise rent from the pool, and always return it.

♻️ Who clears this memory?

stackalloc: the method return (the frame is popped). Span: nothing — it owns nothing; the owner of the memory it points at clears that. Pooled arrays: not freed at all; they are reused until the pool is dropped. new arrays: the GC, after they become unreachable.

🎯 Check yourself
▾ stackalloc inside a loop is fine because the stack space is freed each iteration.

❌ Wrong. Stack space is only released when the method returns, so a loop can overflow the stack.

▾ A Span<T> can be a field of a normal class.

❌ Wrong. It is a ref struct; it cannot live on the heap.

▾ ArrayPool arrays must be returned after use.

✅ Right. Yes — otherwise the pool must allocate new ones.

🔥 Interview recall
  • stackalloc: small, not in loops, not zeroed.
  • Span = pointer + length, no copy; ref struct, no await/heap field.
  • ArrayPool: Rent … Return (finally).
🎤 Say this in an interview
“To reduce GC pressure I avoid temporary heap allocations: Span to slice without copying, stackalloc for small bounded buffers (outside loops), and ArrayPool for larger reusable buffers, always returning them in a finally block.”
⚠️ Common trap

Returning a Span (or storing it) that points at stackalloc memory: the frame is gone after return, so the memory is invalid. The compiler blocks the obvious cases (picture above).
