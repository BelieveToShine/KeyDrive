Concept 8 of 29 · ⚙️ Static & methods

The public calculator on the wall — nobody owns it, everyone uses it.

What a static method call needs (a frame — no object, no this), what a static class is (a container for static members that is never created), and when shared static state bites.

❓ "How does a static method or static class differ from an instance one in memory?"
👁 See it first
🎯 A static method needs no object: just a frame for its parameters and locals; any state it uses lives in static memory.
🌍 In real life

🧮 A calculator bolted to the wall in a shop. Nobody owns it, you never need to “create” one — you walk up and use it. It is great for pure sums (give numbers, get an answer). But if customers also use it to write notes on its scratch pad, everyone sees each other’s notes.

🏛️ What a static class is
Fact (from Microsoft’s docs)Consequence in memory
It cannot be instantiatedno objects of it ever exist on the heap
It can only contain static membersfields in static memory; methods are called with just a frame
It is implicitly sealed — it cannot be inheritedno derived layers (compare page page 13)
It may have a static constructorruns once, before first use (page page 6)
⚡ Performance lens — think like this

Static helpers that only use their parameters allocate nothing and are easy for the GC — a good home for pure maths, formatting and conversion.

Avoid static mutable state: it is shared (bugs), it is a GC root that keeps whatever it references alive (leaks, page page 23), and it makes code hard to test.

A static method that is handed an object (a parameter) can still change that object — see the next page.

🧪 Tiny code
static class Tax
{
    public static decimal Rate = 0.18m;                 // static memory: one copy
    public static decimal Add(decimal x) => x + x * Rate;   // frame: x only — no this
}

var total = Tax.Add(100m);        // 118 — no Tax object exists, none can be created
// var t = new Tax();             // ❌ cannot create an instance of a static class

Static classes are for stateless helpers. If it needs per-user data, use an instance (and let dependency injection manage it — page page 26).

♻️ Who clears this memory?

The frame pops at return. The static field lives until the app ends (page page 6). There is no object to garbage-collect — but anything a static field references stays alive too.

🎯 Check yourself
▾ A static method receives this.

❌ Wrong. It belongs to the type and has no object, so no this.

▾ You can create an instance of a static class with new.

❌ Wrong. A static class cannot be instantiated.

▾ A static method that only uses its parameters allocates no objects.

✅ Right. Right: just a frame.

🔥 Interview recall
  • Static method = frame without this; no object needed.
  • Static class: cannot be created, only static members, implicitly sealed.
  • Static mutable fields are shared by everyone and everything.
🎤 Say this in an interview
“A static method is called on the type, so its frame has no this and no object is needed on the heap. A static class can’t be instantiated and holds only static members. Static fields live for the app’s lifetime and are shared, so I keep static code stateless.”
⚠️ Common trap

Putting per-user or per-request data in a static field “to reach it easily”. It is shared by all users and all threads.
