Concept 5 of 29 · 📚 Stack & heap

A coin in a gift box — when a value must act like an object.

Boxing wraps a value-type value in a heap object; unboxing copies it back. Why it costs memory, and how generics avoid it.

❓ "What are boxing and unboxing, and why can they hurt performance?"
👁 See it first
🎯 Boxing = copying a value into a new heap object so it can be used as an object (or an interface).
🌍 In real life

🪙 A coin (value) fits in your pocket. But the post office only takes parcels (objects). So you put the coin into a gift box and post the box.

Each time you do that, a new box is made — and somebody (the garbage collector) has to throw the empty boxes away later.

🔁 Why boxing in a loop is costly
👀 Where boxing happens without you noticing
CodeWhy it boxes
object o = 5;a value assigned to object
IComparable c = 5;a struct assigned to an interface variable

ArrayList.Add(5)the non-generic list stores object
🧪 Tiny code
int n = 42;
object o = n;          // boxing: new object on the heap holding a copy of 42
n = 99;                // o still holds 42 — the box is a copy
int m = (int)o;        // unboxing: m = 42

var good = new List<int>();   // generic: stores ints directly, no boxing
good.Add(5);

Unboxing to the wrong type throws an InvalidCastException: (long)o on a boxed int fails.

♻️ Who clears this memory?

The box is an ordinary heap object. The garbage collector frees it when no reference points to it. That is exactly why many boxes in a hot loop create GC work.

🎯 Check yourself
▾ object o = 7; creates a heap object.

✅ Right. Yes — the int is boxed into a new object.

▾ After object o = n; n = 99;, o holds 99.

❌ Wrong. The box holds a copy of the old value, 42.

▾ Using List<int> instead of ArrayList avoids boxing.

✅ Right. Right, generics store the value directly.

🔥 Interview recall
  • Boxing: value → new heap object (a copy). Unboxing: copy back.
  • Happens when a value type is used as object or an interface.
  • Costs an allocation + GC work; generics avoid it.
🎤 Say this in an interview
“Boxing copies a value type into a new object on the managed heap so it can be treated as an object or interface; unboxing copies it back. It allocates, so in hot paths I use generics or avoid object-typed APIs.”
⚠️ Common trap

Hidden boxing: a struct passed to an interface-typed parameter or object-typed API is boxed on every call.
