Concept 5 of 29 · 📚 Stack & heap

A coin in a gift box — when a value must act like an object.

Boxing wraps a value-type value in a new heap object (header + type pointer + the value); unboxing copies it back. Why it costs memory, and how generics avoid it.

❓ "What are boxing and unboxing, and why can they hurt performance?"
👁 See it first
🎯 Boxing = copying a value into a new heap object (header + type pointer + the value) so it can be used as an object (or an interface).
🌍 In real life

🪙 A coin (value) fits in your pocket. But the post office only takes parcels (objects). So you put the coin into a gift box with a label on it (the header and type pointer) and post the box.

Each time you do that, a new box is made — and somebody (the garbage collector) has to throw the empty boxes away later.

🔬 Why a boxed int is bigger than an int

A plain int is just its value. A box is a full heap object: an object header, a type pointer to one shared type description, then the value. So boxing costs an allocation, extra memory and later GC work. The type pointer is also what lets unboxing check the type. Exact sizes depend on the runtime version, so the diagram shows the layout, not byte counts (source: Microsoft’s older “How the CLR Creates Runtime Objects” and the Book of the Runtime — a teaching picture).

🧪 Tiny code
int n = 42;
object o = n;          // boxing: new heap object (header + type ptr + a copy of 42)
n = 99;                // o still holds 42: the box is a separate copy
int m = (int)o;        // unboxing: type check, then m = 42

object a = n, b = n;   // boxes twice
// object.ReferenceEquals(a, b) == false  (two different boxes)

var good = new List<int>();   // generic: stores ints directly, no boxing
good.Add(5);

Unboxing to the wrong type throws an InvalidCastException: (long)o on a boxed int fails the type-pointer check.

♻️ Who clears this memory?

The box is an ordinary heap object. The garbage collector frees it when no reference points to it (no root such as a stack variable reaches it) — and only when a GC actually runs. That is exactly why many boxes in a hot loop create GC work.

🔥 Interview recall
  • Boxing: value → new heap object (header + type pointer + a copy). Unboxing: type check, then copy back.
  • Happens when a value type is used as object or an interface.
  • Costs an allocation + memory + GC work; generics avoid it.
🎤 Say this in an interview
“Boxing copies a value type into a new object on the managed heap — header, type pointer and the value — so it can be treated as an object or interface; unboxing checks the type and copies it back. It allocates, so in hot paths I use generics or avoid object-typed APIs.”
⚠️ Common trap

Hidden boxing: a struct passed to an interface-typed parameter or object-typed API is boxed on every call — and each call makes a new box.
