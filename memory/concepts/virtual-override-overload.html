The phone book vs the menu — who decides which method runs?

Overload is chosen by the compiler from the arguments. Override is chosen at run time from the real object. New (hiding) is chosen from the variable’s type. See exactly where each decision is made.

❓ "What is the difference between overloading and overriding, and how does the runtime pick the method?"
👁 See it first
🎯 Overload = the compiler picks by arguments. Override = the runtime picks by the real object. New (hiding) = the compiler picks by the variable’s type.
🌍 In real life

🍽️ The menu (overload): you order “pizza” or “pasta” — the kitchen knows what to make from what you asked for, before cooking starts.

📞 The phone book (override): you ring “Dr. Rao’s clinic” — who actually picks up depends on who is really at the desk right now. You only find out when the call connects.

📞 Override: the real object decides (run time)
🪞 New (hiding): the variable’s type decides

🔬 Honest note

Microsoft documents the behaviour of virtual, override and new (above). Exactly how the runtime stores each type’s method list is an implementation detail; the lab draws it as a simple “type info” box and does not quote sizes or addresses.

🧪 Tiny code
class Animal
{
    public virtual void Speak() => Console.WriteLine("...");     // can be overridden
    public void Print(int n)    => Console.WriteLine("int");     // overload 1
    public void Print(string s) => Console.WriteLine("string");  // overload 2
}
class Dog : Animal
{
    public override void Speak() => Console.WriteLine("Woof");   // object decides
    // public new void Speak()   => ...                          // variable's type decides
}

Animal a = new Dog();
a.Speak();       // Woof       (override: run time, by the real object)
a.Print(5);      // int        (overload: compile time, by the argument type)

Use override for polymorphism. new hides — it rarely does what you meant.

♻️ Who clears this memory?

Nothing special: method calls use stack frames (page 2) that pop on return. Dispatch itself allocates no heap memory — the objects involved are cleaned by the GC like any others.

🎯 Check yourself
▾ Overload resolution happens while the program runs.

❌ Wrong. It is done by the compiler when you build.

▾ A virtual call runs the method of the object’s real type.

✅ Right. Yes — decided at run time.

▾ With new hiding, Animal a = new Dog(); a.Speak(); runs Dog.Speak.

❌ Wrong. It runs Animal.Speak: the variable’s type decides.

🔥 Interview recall
  • Overload: compile time, by arguments.
  • Override (virtual): run time, by the object’s real type.
  • new (hiding): compile time, by the variable’s type.
🎤 Say this in an interview
“Overloads are resolved by the compiler from the argument types. Virtual methods are resolved at run time from the object’s actual type, which is how polymorphism works. A member hidden with new is resolved at compile time from the variable’s declared type.”
⚠️ Common trap

Hiding a method with new and expecting polymorphism. Through a base-typed variable you get the base version.
