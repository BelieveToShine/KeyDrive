Concept 3 of 29 · 📚 Stack & heap

A photo you copy versus a house address you share.

What a variable holds: the data itself (value types) or an address (reference types) — and what a copy does in each case.

❓ "What is the difference between value types and reference types in memory?"
👁 See it first
🎯 A value-type variable holds the data. A reference-type variable holds the address of an object.
🌍 In real life

📷 A value is like a photo. If I give you a copy of my photo and you scribble on it, my photo is unchanged.

🏠 A reference is like a house address on a card. If I copy the card, we both have the address of the same house. If you repaint the house, I see it painted too.

🏠 Reference types: copying the address
📦 A value inside an object
🧳 A struct that holds a reference (shallow copy)

🔤 What about string?

string is a reference type: a Name field holds a reference to a separate string object on the heap that holds the characters (second picture). It is also immutable: “changing” a string makes a new string object and re-points the reference. That is why a loop that glues strings together creates many short-lived objects.

One special case: string literals such as "Asha" are kept by the runtime in an intern table, so that particular string stays around. A string built at run time that nothing points to is what the GC frees.

🔬 Honest note

The header and type pointer on a heap object come from Microsoft’s older article “How the CLR Creates Runtime Objects” and the .NET runtime’s Book of the Runtime (classic model; exact widths and layout vary by version). The addresses (0x…A1) and the cell order in the pictures are a teaching picture: the runtime may reorder fields and the GC may move objects.

🧪 Tiny code
struct Point { public int X; }          // value type
class  Person { public string Name; }   // reference type

var a = new Point { X = 1 };
var b = a;      b.X = 9;                // a.X is still 1  (copy)

var p1 = new Person { Name = "Asha" };
var p2 = p1;    p2.Name = "Ravi";       // p1.Name is now "Ravi"  (shared)

Passing an argument works the same way: a value is copied into the parameter slot; a reference copies the address.

♻️ Who clears this memory?

Value on the stack: gone when the frame pops. Value inside an object: gone when the GC frees that object. Reference-type object: freed by the GC some time after no reference (from any variable) points to it — being unreachable and being freed are different moments.

🎯 Check yourself
▾ After var p2 = p1;, there are two Person objects.

❌ Wrong. Still one object; there are two references to it.

▾ int fields of a class live inside the object on the heap.

✅ Right. Yes. Where a value lives follows its variable.

▾ Changing a copied struct changes the original.

❌ Wrong. A struct copy is independent, like a copied int.

▾ Copying a struct that holds a reference also copies the object it points to.

❌ Wrong. Only the reference (address) is copied; both structs share the one object.

🔥 Interview recall
  • Value type variable = the data. Reference type variable = the address.
  • Copying a value copies data; copying a reference shares the object.
  • A value type inside an object lives inside that object (heap).
  • A struct copy copies its references as references (shallow).
🎤 Say this in an interview
“Value types hold their data where the variable lives, so assignment copies the data. Reference types hold a reference to a heap object, so assignment copies the reference and both variables see the same object.”
⚠️ Common trap

Saying “structs always live on the stack and classes on the heap.” A struct field inside a class is on the heap; a struct in an array is inside the array on the heap.
