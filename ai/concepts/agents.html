Concept 11 of 19 · 🤖 Acting on goals

An agent pursues a goal across multiple steps, not just one response.

Prompting, RAG, and fine-tuning all improve one response. Agents exist for goals that need more than one — search, check, decide, adjust, repeat. The most common way to build one is the loop below, but that loop is an architecture, not the only possible definition.

❓ "Why can't a single prompt-response handle a multi-step goal?"
👁 See it first
🎯 An agent = a system that uses a model to pursue a goal, choosing actions and using real feedback to make progress — commonly built as a plan-act-observe loop.
▶️ Watch it happen: the agent loop
📖 Why did this need to exist?

A single prompt-response is a one-shot answer — it can't take an action, see what actually happened, and adjust based on that. Many real goals need exactly that: search for something, check whether the result is good enough, decide whether to search again or refine the approach.

An agent is a system that uses a model to pursue a goal, choosing actions and using feedback from the environment to make progress. The plan-act-observe loop is the most common architecture for this — plan a step, act on it, observe the real outcome, repeat — but it's one common shape, not the only possible one; some agent designs branch, run steps in parallel, or hand off between specialized sub-agents. The loop is worth learning well because it underlies most of what you'll actually build.

Each piece of this loop opens its own question, coming up next in this journey: what does "act" actually mean, concretely (Tools)? How does the agent remember what happened in earlier iterations of the loop (Memory)? The loop itself is the important shape to hold onto — everything else in this section of the journey is a capability that loop draws on.

🔥 Interview recall
  • An agent uses a model to pursue a goal, choosing actions and using real feedback — commonly built as plan → act → observe → repeat, until the goal is met.
  • It exists because a single prompt-response can't see the result of its own action.
  • "Observe" must be a real result — not the model imagining what probably happened.
  • Tools, Memory, and Planning are capabilities this loop draws on, not separate loops.
🎤 Say this in an interview
"An agent is a system that uses a model to pursue a goal, choosing actions and using feedback from the environment to make progress. The most common architecture is a plan-act-observe loop: plan the next step, take that action, observe the real result, and use it to plan the next step — repeating until the goal is satisfied. That's different from a single prompt-response, which can't see or react to the outcome of its own action."
⚠️ Common trap

An agent isn't just "an LLM asked to take more steps." The loop only works if "observe" reflects a real outcome — a real search result, a real API response — not the model guessing what probably happened. That real feedback requires tools that actually do things and return real results, which is exactly the next concept.

💬 Prompting

One-shot: ask, get an answer. No loop, no observation.

vs.
🔁 Agent

Loop: plan, act, observe, repeat — until the goal is actually met.

▾ 💻 Tiny illustrative example 
# The agent loop, at the shape level
while not goal_met(state):
    step   = plan(goal, state)        # decide what to do next
    result = act(step)                # actually do it
    state  = observe(result, state)   # update understanding from the real outcome
# loop exits only once the goal is actually satisfied

Illustrative shape only — real agent loops add limits, error handling, and stopping conditions around this core idea.
