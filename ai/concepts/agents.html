Concept 10 of 17 · 🤖 Acting on goals

An agent is a model wrapped in a loop that keeps going until the goal is actually met.

Prompting, RAG, and fine-tuning all improve one response. Agents exist for goals that need more than one response — search, check, decide, adjust, repeat.

❓ "Why can't a single prompt-response handle a multi-step goal?"
👁 See it first
🎯 Agents = wrapping a model in a loop — plan, act, observe, repeat — until a goal is actually met.
📖 Why did this need to exist?

A single prompt-response is a one-shot answer — it can't take an action, see what actually happened, and adjust based on that. Many real goals need exactly that: search for something, check whether the result is good enough, decide whether to search again or refine the approach.

Agents wrap the model in a loop that plans a step, acts on it, observes the real outcome, and repeats — until the goal is satisfied, not just until the model finishes generating one reply.

▾ Go one level deeper (60 seconds)

Each piece of this loop opens its own question, coming up next in this journey: what does "act" actually mean, concretely (Tools)? How does the agent remember what happened in earlier iterations of the loop (Memory)? And for a genuinely complex goal, how does it decide the right order of steps up front, rather than figuring it out one step at a time (Planning)?

The loop itself is the important shape to hold onto — everything else in this section of the journey is a capability that loop draws on.

🔥 Interview recall
  • Agent = plan → act → observe → repeat, until the goal is met.
  • It exists because a single prompt-response can't see the result of its own action.
  • "Observe" must be a real result — not the model imagining what probably happened.
  • Tools, Memory, and Planning are capabilities this loop draws on, not separate loops.
🎤 Say this in an interview
"An agent wraps a model in a loop: it plans the next step toward a goal, takes that action, observes the real result, and uses that observation to plan the next step — repeating until the goal is actually satisfied. That's different from a single prompt-response, which can't see or react to the outcome of its own action."
⚠️ Common trap

An agent isn't just "an LLM asked to take more steps." The loop only works if "observe" reflects a real outcome — a real search result, a real API response — not the model guessing what probably happened. That real feedback requires tools that actually do things and return real results, which is exactly the next concept.

💬 Prompting

One-shot: ask, get an answer. No loop, no observation.

vs.
🔁 Agent

Loop: plan, act, observe, repeat — until the goal is actually met.

▾ 💻 Tiny illustrative example 
# The agent loop, at the shape level
while not goal_met(state):
    step   = plan(goal, state)        # decide what to do next
    result = act(step)                # actually do it
    state  = observe(result, state)   # update understanding from the real outcome
# loop exits only once the goal is actually satisfied

Illustrative shape only — real agent loops add limits, error handling, and stopping conditions around this core idea.
