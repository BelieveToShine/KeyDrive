Concept 9 of 17 · 🛠️ Using the model

Fine-tuning makes a behavior permanent, instead of something you re-ask for every time.

Prompting and RAG both work at inference time and leave the model unchanged. Fine-tuning is the option that actually updates the model's own weights, for when a behavior needs to stick.

❓ "When would you fine-tune a model instead of just prompting it better?"
👁 See it first
🎯 Fine-tuning = training the model further on examples of the exact behavior you want, so it becomes permanent.
📖 Why did this need to exist?

Prompting and RAG both work at inference time — they don't change the model, so their effects last only for that one request. Some needs are better solved permanently: a consistent tone across every response, a narrow specialized skill, reliably following a specific format without being reminded.

Fine-tuning updates the model's own weights using examples of the desired behavior, so that behavior becomes built in rather than something to re-specify every single time.

▾ Go one level deeper (60 seconds)

Fine-tuning starts from the already-trained base model — it isn't training from scratch. It's additional training on a smaller, focused set of examples that nudges the existing weights toward the desired behavior, reusing everything the base model already learned rather than relearning language from zero.

This is the same training vocabulary from Machine Learning and Neural Networks — labeled examples, an adjustment process, weights that change — just applied a second time, on top of an already-capable model instead of starting blank.

🔥 Interview recall
  • Fine-tuning updates the model's actual weights — the only one of the three that does.
  • It exists for behavior that needs to be permanent, not re-specified every request.
  • It starts from the trained base model, not from scratch.
  • Best for style/skill consistency — not for adding facts (RAG) or one-off steering (prompting).
🎤 Say this in an interview
"Fine-tuning takes an already-trained model and trains it further on a curated set of examples showing the exact behavior you want, updating its weights so that behavior becomes permanent. Unlike prompting or RAG, which only affect a single request, fine-tuning changes the model itself."
⚠️ Common trap

Fine-tuning isn't the first thing to reach for. It needs curated training examples and an actual training run — more effort than writing a better prompt, and the wrong tool for adding facts (that's RAG). Reach for it specifically when the goal is consistent style, tone, or a narrow skill that should hold across every request without re-explaining it.

📚 RAG

Adds facts per-request. No weight change, no permanence.

vs.
🔧 Fine-tuning

Changes the model's weights. Permanent behavior change, not per-request.

▾ 💻 Tiny illustrative example 
# Fine-tuning: further training on curated examples of the desired behavior
base_model = load_llm()
examples = [
    {"input": "...", "output": "...(in the exact desired style)..."},
    # many more examples of the same style/skill
]
specialized_model = fine_tune(base_model, examples)  # weights updated, permanently

Illustrative shape only — real fine-tuning involves careful data curation and evaluation to avoid degrading other capabilities.
