Concept 9 of 19 · 🛠️ Using the model

RAG hands the model real documents, instead of hoping it remembers.

Prompting steers behavior, but it can't teach the model facts it never saw. RAG (Retrieval-Augmented Generation) is how you give it current, private, or simply new knowledge — without retraining anything.

❓ "How does RAG let a model answer questions about data it was never trained on?"
👁 See it first
🎯 RAG = retrieve the most relevant real documents, then hand them to the model alongside the question.
📖 Why did this need to exist?

An LLM's knowledge is frozen at training time — it has a cutoff, and it never saw an organization's private or fast-changing information (this week's policy update, a customer's own account data, internal documentation). Prompting alone can't fix this: it steers behavior, but it can't hand the model facts that simply aren't in its weights.

RAG closes that gap at query time: it retrieves the most relevant material from an external knowledge base and adds it directly into the prompt, so the model answers using facts it was never trained on — without anyone retraining it.

▾ Go one level deeper (60 seconds)

"Retrieve" almost always means searching by meaning, not just matching keywords. Documents and the question both get converted into embeddings — numeric representations of meaning — so a question about "time off rules" can still find a document about "vacation policy" even though they don't share a single word.

RAG doesn't change the model at all — it changes what's in the prompt for that one request. If the knowledge base genuinely doesn't contain the answer, RAG can't invent it; it can only surface what's actually there.

🔥 Interview recall
  • RAG = retrieve relevant chunks, then add them to the prompt before the model answers.
  • It exists because a model's knowledge is frozen at training time and can't include private/current data.
  • Retrieval usually matches by meaning (embeddings), not just keywords.
  • RAG changes the prompt for one request — it doesn't retrain or permanently change the model.
🎤 Say this in an interview
"RAG retrieves the most relevant documents for a question from an external knowledge base, usually by comparing meaning through embeddings, and adds them to the prompt before the model generates an answer. It lets the model use knowledge it was never trained on, without any retraining — the model's weights never change."
⚠️ Common trap

RAG doesn't retrain the model, and it can't invent missing knowledge. It only changes what's in that one prompt. If the knowledge base doesn't actually contain the answer, retrieval can't manufacture it — the model is still limited to whatever got retrieved plus whatever it already knew from training.

💬 Prompting

Steers behavior through instructions. No new facts added.

vs.
📚 RAG

Adds retrieved facts to the prompt. Both happen at inference time — neither changes weights.

▾ 💻 Tiny illustrative example 
# Retrieve, then augment the prompt with what was found
chunks = knowledge_base.search(question, top_k=3)  # matched by meaning, not keywords

prompt = f"Answer using only this context:\n{chunks}\n\nQuestion: {question}"
answer = model.generate(prompt)  # same frozen model — now grounded in real docs

Illustrative shape only — real RAG systems add chunking, ranking, and citation handling around this core idea.
