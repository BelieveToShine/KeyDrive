Prompting changes the instruction, RAG changes the facts, fine-tuning changes the model — pick the lightest one that fixes the real problem.

A decision tree, a side-by-side table and six real scenarios for the choice every AI builder faces.

❓ "When would you use prompting, RAG or fine-tuning?"
👁 See it first
🎯 Prompting changes the instruction, RAG changes the facts the model sees, fine-tuning changes the model itself — pick the lightest one that fixes the real problem.
▶️ Watch it happen: pick the lightest fix
📖 Why did this need to exist?

Three pages in a row gave you three tools. The mistake teams make is reaching for the heaviest one first: fine-tuning a model to teach it facts that RAG would supply, or building retrieval to fix what a clearer prompt would have solved.

The decision comes down to what is missing: clarity (prompt), knowledge (RAG) or built-in behaviour (fine-tune). Name the gap first, then pick the tool.

🧰 The three tools

💬 Prompting

change the instruction✅ Pick it when
  • Wrong tone, format or steps
  • You can describe what you want in words
  • You want to try ideas in minutes
⛔ Look elsewhere when
  • The model simply does not have the facts
  • The behaviour must persist without being re-asked

📚 RAG

supply the facts at question time✅ Pick it when
  • Private, new or fast-changing information
  • Answers should point to source documents
  • The knowledge base is too big to paste in
⛔ Look elsewhere when
  • The knowledge base does not contain the answer — RAG cannot invent it
  • The problem is style, not facts

🎯 Fine-tuning

change the weights✅ Pick it when
  • A consistent tone or format that prompts cannot hold
  • A narrow skill shown best by many examples
  • You have good examples of the exact behaviour
⛔ Look elsewhere when
  • You mainly need current facts — use RAG
  • You have few or poor examples

▾ Go one level deeper (60 seconds) — how to decide with evidence

Measure first. Build a small test set (see Evaluation, concept 17) before you change anything. Without it you cannot tell whether a prompt change, a retrieval change or a fine-tune actually helped.

Look at the failures. If the failing answers contain wrong facts, think RAG. If they contain the right facts in the wrong shape, think prompt or fine-tune. If retrieval returns the wrong documents, fix retrieval before blaming the model.

Fine-tuning is not for facts. It shapes behaviour from examples; it is a poor and costly way to keep knowledge current.

🔥 Interview recall
  • Prompting = change the instruction. RAG = supply facts at question time. Fine-tuning = change the weights.
  • Name the gap first: clarity, knowledge or built-in behaviour.
  • Start light (prompting), move right only when needed, and measure each step.
  • RAG cannot invent facts the knowledge base lacks; fine-tuning is not a good way to teach changing facts.
  • Real systems combine them.
🎤 Say this in an interview
"I decide by what is missing. If the instruction is unclear I improve the prompt; if the model lacks private or current facts I add RAG; if a behaviour must hold every time and prompts cannot keep it there, I consider fine-tuning. I start with the lightest option, measure with a test set, and combine them when the problem has more than one gap."
⚠️ Common trap

Fine-tuning to add facts. It is slow to update and the facts go stale. If the problem is knowledge, retrieval fits better.

Second trap: skipping measurement. Without a test set you will "fix" things that were fine and miss things that broke.

📚 RAG

Adds knowledge at question time. The model stays the same.

vs.
🎯 Fine-tuning

Changes behaviour permanently. Facts freeze at training time.
