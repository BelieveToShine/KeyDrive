Concept 8 of 19 · 🛠️ Using the model

Prompting steers a model's behavior without changing a single weight.

You now have a large, capable, expensive-to-train model. Prompting is the fastest way to point that same frozen model at a specific task — just by changing what you ask it.

❓ "How can changing a prompt change model behavior if the weights never change?"
👁 See it first
🎯 Prompting = steering a frozen model's behavior through the input text itself, not by retraining it.
📖 Why did this need to exist?

Retraining a large model for every new task or instruction is far too slow and expensive to do routinely — training is the "happens once, offline" step from Machine Learning, and it stays that way for a reason.

Prompting solves this by steering behavior entirely at inference time: the same frozen weights, given a different instruction in the input, produce different behavior. No training run, no weight changes — just a different request to the same capability.

▾ Go one level deeper (60 seconds)

This works because of what an LLM actually learned during training: not one fixed task, but an extremely broad ability to continue text in a way that fits its instructions and context. A prompt is just the starting context — asking it to summarize, translate, or explain simply are all just different contexts for the same underlying capability to act on.

Prompting has a ceiling, though: it can't give the model facts it was never trained on, or permanently change how it behaves next session. Those are exactly the gaps RAG and fine-tuning exist to close, next in this journey.

🔥 Interview recall
  • Prompting steers behavior at inference time — no weights change.
  • It exists because retraining for every task/instruction is impractical.
  • The same frozen model, different instruction, different behavior.
  • Prompting can't add new knowledge or make a permanent behavior change — see RAG and Fine-tuning.
🎤 Say this in an interview
"Prompting steers a model's behavior purely through the input text, at inference time, with no change to the model's weights. It works because the model learned a broad ability to continue text according to its context — different instructions are different contexts for that same underlying capability."
⚠️ Common trap

Prompting changes behavior, not knowledge. No matter how cleverly worded, a prompt can't teach the model a fact it was never trained on, and it doesn't persist — the next separate conversation starts from the same frozen weights again. Giving it new facts is RAG's job; making a change stick is fine-tuning's job.

▾ 💻 Tiny illustrative example 
# Same frozen model, two different prompts
model = load_llm()   # weights loaded once, never change below

summary  = model.generate("Summarize this in one sentence: ...")
explainer = model.generate("Explain this like I'm five: ...")
# model.weights are identical in both calls — only the prompt differs

Illustrative only — real prompting often involves more structure (system messages, examples), but the core idea is exactly this.
