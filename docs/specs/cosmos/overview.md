# Cosmos DB Performance Lab — overview
Part of Data Systems (plan: `docs/specs/data/overview.md`, taxonomy: `docs/specs/data/concept-taxonomy.md` Track B). **API: Azure Cosmos DB for NoSQL only** (the SQL-like query language); MongoDB/Cassandra/Gremlin/Table are out of scope. Folder `cosmos/`, hub generated by `scripts/page-kit/cosmos/build_hub.py`, wiring by `scripts/page-kit/cosmos/wire_page.py`, ledger additions by `scripts/page-kit/cosmos/ledger_add.py`.

Page rhythm = the SQL lab's: See it first → Why → how it works → pick-cards/tables → **Plan lab** (before/after picture + the **RU charge**) → **Debug checklist** (symptom → cause → fix) → scenarios → recall / interview / trap / confuse-pair → next. Ladder (Cosmos wording): measure the RU charge → read the diagnostics → find the biggest wrong thing → one hypothesis → one change → prove.

## Canonical numbers (keep every page consistent — grep before reusing)
| Fact | Value |
|---|---|
| Account shape | container `orders` (partition key chosen on page 2: `/customerId`), `customers`, `products` |
| Size | ~1,000,000 orders (≈ 2 KB each, lines embedded), ~50,000 customers → ~20 orders per customer |
| BigCorp | customer 7 with 80,000 orders ≈ 160 MB — a big logical partition, far below the 20 GB limit |
| Physical partitions (illustrative) | the orders container has about 50 physical partitions |
| Costs used for teaching | point read ≈ 1 RU per 1 KB (a 2 KB order ≈ 1–2 RU); write ≈ 5 RU per 1 KB with default indexing (a 2 KB order ≈ 10 RU); each physical partition checked by a cross-partition query ≥ 2.5 RU (≈ 125 RU for 50) |
| Throughput examples | autoscale max 10,000 RU/s (floor 1,000); 1–5% 429s is healthy |
