📖 Why did this need to exist?

In the React lab, page 8 asked “who owns this state, and who reads it?” and answered with local state, lifting, context and reducers. Angular asks the same question and has a more direct answer: dependency injection (page 7) plus signals (page 5) already give you shared, reactive state.

A service with signals covers most apps. Libraries such as NgRx add structure — actions, reducers, effects, or the lighter SignalStore — for large teams and many features.

This page shows the service pattern, how to choose the scope, and when a store library is worth its cost. NgRx is a third-party library: its own docs are the authority.

🏗️ The state-service pattern
🧪 State lab · the ShopUI cart
@Injectable({ providedIn: 'root' })
export class CartService {
  private _items = signal<CartItem[]>([]);
  readonly items = this._items.asReadonly();                      // components cannot .set() it
  readonly count = computed(() => this._items().length);
  readonly total = computed(() => this._items().reduce((s, i) => s + i.price, 0));

  add(item: CartItem) { this._items.update(l => [...l, item]); }      // immutable update (page 3)
  remove(id: string)  { this._items.update(l => l.filter(i => i.id !== id)); }
}

Illustrative sketch. asReadonly() exposes a read-only view of a writable signal.

▾ Go one level deeper (60 seconds)

Scope = provider. Where you provide the service sets its lifetime: root = app lifetime; component or route = that subtree’s lifetime (page 7).

Async state. Resources (resource, httpResource) expose data, loading status and error as signals, so a service can hold server state without hand-written loading flags (page 5).

Compare with React. Context + reducer in React corresponds to a root service with signals in Angular; both put one owner in front of many readers.

🔥 Interview recall
  • Default to a signal in the component; share through a service that owns signals.
  • Expose read-only signals and methods; keep the writable signal private (asReadonly()).
  • Provide at root for app-wide state; at component or route level for scoped state.
  • Update arrays and objects immutably so OnPush and computed see the change.
  • NgRx SignalStore (withState, withComputed, withMethods) is a third-party option when structure is needed.
  • Do not use a store for local UI state.
🎤 Say this in an interview
"Shared state in Angular is a service that owns signals: a private writable signal, read-only computed values and methods that change it, provided at root for app-wide state or per component for scoped state. Updates are immutable. I bring in a store library like NgRx SignalStore only when many features need enforced structure."
⚠️ Common trap

Exposing a writable signal. Anyone can change it and nobody can trace it.

A store library for a dropdown flag. More code, no benefit.
