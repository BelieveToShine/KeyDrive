👁 See it first
🎯 A template is code that runs on every check: keep it cheap, give loops a unique track, and compute values once, not on every pass.
▶️ Watch it happen: templates run on every check
📖 Why did this need to exist?

Page 3 reduced how many components are checked. This page is about what each check does: it re-evaluates every expression in the template. A loop over 500 items, a method call in a binding, a heavy pipe — each multiplies.

Modern Angular templates have built-in control flow — @if, @for, @switch — that replaced the older *ngIf/*ngFor directives. @for forces you to say how to track items, which is exactly the identity question React answers with keys (React lab, page 3).

Pipes transform values for display. Pure pipes only re-run when their input changes; this is the template-level version of memoization.

@switch (x) { @case (…) { … } @default { … } }Compares with ===; no fall-through; @default optionalWith no match and no default, nothing is shown

What to track. Use a unique property such as id; for a static list $index is fine; tracking by the item itself is a last resort because it can lead to significantly slower updates. A track expression may only use $index, the item, and members of the component. Unlike the old *ngFor, @for prioritises reusing views.

▾ Go one level deeper (60 seconds)

Expressions. Template expressions run against the component; a template variable with the same name as a class member shadows it. Declarations such as functions or classes are not supported inside expressions.

ng-template. It declares a fragment that can be rendered dynamically; its expressions are evaluated against the component that declares it, wherever it is rendered. Content projection (ng-content) is covered in the component-communication dive.

Exhaustive switches. @default never; makes the compiler check that every case is handled, when the switched value is a plain variable.

🔥 Interview recall
  • @for needs track; use a unique id; item identity is a last resort.
  • @if / @else, @switch, @empty, @let are built-in control flow.
  • Template expressions re-run on every check of that component.
  • Pure pipes re-run only when their input changes; impure pipes run every cycle.
  • Prefer a pure pipe or computed() to a method call in a binding.
  • AsyncPipe subscribes, marks for check and unsubscribes for you.
🎤 Say this in an interview
"A template is re-evaluated on every check, so I keep it cheap: @for always tracks by a unique id so Angular reuses DOM nodes, values are derived with computed or pure pipes instead of method calls, and impure pipes are avoided. Built-in control flow replaces the old structural directives."
⚠️ Common trap

Tracking by $index in a list that changes. State and focus stick to positions.

Calling methods from bindings. They run on every check, for every instance.

🧮 Pure pipe

Re-runs only when its input changes; safe for formatting.

vs.
🔁 Impure pipe

Re-runs on every change-detection cycle; use only when unavoidable.
