Streams over time — and every subscription needs an end.

When RxJS beats signals, the three safe ways to subscribe, and how switchMap, mergeMap, concatMap and exhaustMap decide what happens to an earlier request.

👁 See it first
🎯 An Observable is a stream of values over time. Angular uses it for HTTP, router events and forms — and you must make sure subscriptions end.
▶️ Watch it happen: a stream over time
📖 Why did this need to exist?

Signals (page 5) hold the current value. But much of the web is events over time: keystrokes, HTTP responses, websocket messages, route changes. RxJS models those as observables and gives you operators to combine, delay, cancel and retry them. Angular’s HttpClient, router and forms are built on observables.

The cost is the subscription: someone must listen, and someone must stop listening. A forgotten subscription is the classic Angular memory leak.

This page covers when RxJS is the right tool, the three ways to subscribe safely, and the flattening operators that decide what happens when a new event arrives while the last is unfinished. The operator reference has its own deep dive.

🧪 RxJS lab · the search box
results = toSignal(
  toObservable(this.query).pipe(
    debounceTime(300),                       // wait for a pause in typing
    distinctUntilChanged(),                  // skip repeats
    switchMap(q => this.http.get<Product[]>(`/api/products?q=${q}`)),   // cancel the old request
  ),
  { initialValue: [] },
);

Illustrative sketch. The 300 ms pause is a teaching value. The pipeline is created once; toSignal cleans it up with the component.

▾ Go one level deeper (60 seconds)

Flattening operators (from the RxJS docs): switchMap stops the earlier inner observable when a new one arrives; mergeMap subscribes to each as it arrives and interleaves outputs; concatMap equals mergeMap with concurrency 1; exhaustMap ignores new inner observables until the previous completes. The operator deep dive covers each with a diagram.

Cold observables. An HttpClient call is normally a cold observable: it starts when subscribed, so each subscription can start its own request. Share or convert once if you read it in several places.

Async pipe also switches subscription when the bound expression’s reference changes.

🔥 Interview recall
  • An Observable is a stream of values over time; HttpClient, the router and forms use them.
  • Every subscription needs an end: async pipe, toSignal, takeUntilDestroyed (stable since v19) — or manual unsubscribe.
  • switchMap cancels the old; mergeMap runs all; concatMap queues; exhaustMap ignores new until done.
  • Use signals for current state; RxJS for events over time and cancellation.
  • debounceTime + distinctUntilChanged + switchMap is the classic search pipeline.
  • Handle errors inside the inner observable so one failure does not end the stream.
🎤 Say this in an interview
"I use signals for state the template reads and RxJS for events over time. I never leave a subscription open: the async pipe, toSignal and takeUntilDestroyed clean up when the component is destroyed. For search I debounce, drop repeats and switchMap so stale requests are cancelled, and I choose the flattening operator by what should happen when a new event arrives mid-request."
⚠️ Common trap

subscribe() in ngOnInit with no cleanup. The most common Angular leak.

mergeMap for search. Answers arrive out of order; use switchMap.
