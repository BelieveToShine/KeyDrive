Deep dive · Angular lab · 🧪 Testing

Test the behaviour — and wait for Angular to settle.

TestBed setup, fake services, why tests must wait for stability in a zoneless world, component harnesses, and what not to test.

❓ "How do you unit test an Angular component, and what changed with zoneless testing?"
👁 See it first
🎯 Test the behaviour, give the component a fake for each service, and wait for stability before asserting.
📖 Why did this need to exist?

The clinic fixes — OnPush, signals, a different track — must not change what the screen does. Tests are how you know. They also teach you whether your design is injectable: a component that cannot be given a fake cart is hard to test and hard to reuse (page 7).

Modern Angular adds one twist: TestBed uses zoneless change detection by default, even if zone.js is loaded. Updates are no longer “magically” flushed after every task, so tests must wait for the app to settle.

This page covers the TestBed setup, waiting for stability, component harnesses and what to leave out of unit tests.

🧪 Testing lab · ShopUI cart badge
it('shows the count after adding an item', async () => {
  TestBed.configureTestingModule({
    imports: [CartButton],
    providers: [{ provide: CartService, useClass: FakeCartService }],
  });
  const fixture = TestBed.createComponent(CartButton);
  await fixture.whenStable();                              // initial render
  fixture.nativeElement.querySelector('button').click();
  await fixture.whenStable();
  expect(fixture.nativeElement.textContent).toContain('Cart (1)');
});

Illustrative sketch. The fake service has a signal-based count; the test never reads a private field.

▾ Go one level deeper (60 seconds)

Zoneless TestBed. TestBed uses zoneless change detection by default, even when zone.js is loaded through polyfills; the docs say to avoid detectChanges() where possible.

Harnesses. The CDK’s component harnesses give tests a stable API over a component’s DOM, so template refactors do not break them.

Provider name. The zoneless provider was experimental in v19 (provideExperimentalZonelessChangeDetection); current docs use provideZonelessChangeDetection.

🔥 Interview recall
  • Test behaviour: rendered text, inputs, outputs, service interactions; not private fields or CD counts.
  • Replace services with fakes through TestBed providers.
  • TestBed is zoneless by default; wait with await fixture.whenStable().
  • Avoid fixture.detectChanges() where possible; automatic change detection is on by default in zoneless tests.
  • TestBed enforces OnPush-compatibility (NG0100 if values change without notification).
  • Harnesses give stable DOM access.
🎤 Say this in an interview
"I test components through their public behaviour, with fake services supplied through TestBed providers, and since TestBed is zoneless by default I await fixture.whenStable rather than relying on zone.js. I use harnesses for DOM access and leave change-detection counts to the profiler."

Testing private fields. Every refactor breaks tests that nobody can explain.
