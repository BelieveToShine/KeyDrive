📖 Why did this need to exist?

Pages 2–4 cut the cost of change detection; page 9 cut the first bundle by route. Two parts of the first-load story remain: within a page, heavy blocks (charts, reviews, a map) that are not needed immediately; and time to first content, which is slow when everything starts as an empty page waiting for JavaScript.

Angular answers the first with @defer and the second with server-side rendering (SSR) plus hydration. They connect: on the server a defer block renders its placeholder; incremental hydration lets parts of the page stay dehydrated until needed.

The same trade-offs appeared in the React lab (bundles, server rendering). The ideas match; the APIs differ.

On the server, defer blocks always render their @placeholder and triggers are not invoked. A hydrate trigger (incremental hydration) tells Angular to render the block’s main content on the server and hydrate it later.

🖥️ SSR, hydration and event replay
🧪 Performance lab · ShopUI first load
// Reviews and the recommendation carousel are below the fold
@defer (on viewport; prefetch on idle) {
  <app-reviews [productId]="id()" />
} @placeholder (minimum 300ms) {
  <div class="skeleton"></div>
} @loading (after 100ms; minimum 500ms) {
  <app-spinner />
} @error {
  <p>Reviews could not load.</p>
}

Illustrative sketch; the millisecond values are teaching values. Defer content that is below the fold or behind an interaction.

▾ Go one level deeper (60 seconds)

Enabling hydration. CLI-created SSR projects usually include it; otherwise add provideClientHydration() to the client bootstrap providers and to the server bootstrap providers.

Incremental hydration. Hydrate triggers (idle, viewport, interaction, hover, immediate, timer, when, or never) are used with @defer (hydrate on …); nested blocks hydrate parent-first. Docs describe it as developer preview in v19 and stable in v20 — check your version.

ngSkipHydration on a component host skips hydrating it and its children; the docs call components that break hydration bugs to be fixed.

🔥 Interview recall
  • @defer splits a block’s dependencies into a separate file loaded on a trigger; placeholder, loading and error blocks are eager.
  • Triggers: idle (default), viewport, interaction, hover, immediate, timer, when; combine with semicolons; prefetch loads early.
  • On the server defer renders the placeholder; hydrate triggers enable incremental hydration.
  • Hydration reuses the server DOM; event replay re-dispatches early clicks; mismatches raise NG0500.
  • ngSkipHydration is a last resort.
  • Measure first-load JavaScript and time to content before and after each change.
🎤 Say this in an interview
"I keep the first load small: lazy routes, then @defer for below-the-fold or interaction-only blocks with a sized placeholder, and prefetch on idle. For fast first content I use SSR with hydration and event replay, avoid DOM edits outside Angular to prevent NG0500, and use incremental hydration where it pays. I measure before and after."
⚠️ Common trap

Deferring something visible at first paint. It flashes a placeholder and shifts layout.

Manipulating the DOM with native APIs in an SSR app. It breaks hydration.
