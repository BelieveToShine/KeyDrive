Concept 2 of 12 · 🅰️ The update model

Angular must notice that something changed — and the cost is how much it checks.

What change detection is, how zone.js and zoneless start a pass, and how Eager and OnPush strategies decide how much of the tree to check.

❓ "How does Angular know when to update the view, and what is the difference between Default and OnPush?"
👁 See it first
🎯 Change detection is Angular re-checking templates to update the DOM. Its cost is how many components it checks — so the job is to make Angular check fewer.
▶️ Watch it happen: checking fewer components
📖 Why did this need to exist?

Page 1 gave you a tree of components with bindings. A binding like {{ product().name }} shows a value; if the value changes, the DOM must change. Somebody has to notice. That somebody is change detection: Angular walks the tree, re-evaluates each component’s template expressions, and updates the DOM where a value differs.

Two questions decide the cost: when does Angular start a pass (the trigger), and how much of the tree does a pass visit (the strategy)? For years the answers were “after anything async, thanks to zone.js” and “everything”. Modern Angular lets you answer “only when told” and “only what is dirty”.

This page is the map: triggers (with and without zone.js) and strategies (Eager and OnPush). Page 3 shows how to opt in with OnPush and signals.

An app created years ago almost certainly uses zone.js and Eager components.

▾ Go one level deeper (60 seconds)

Events inside an OnPush subtree check the ancestors too. An event in a component marks it and its ancestors dirty, so the path from the event up to the root is checked even if those ancestors are OnPush.

Dev-mode second pass. In development Angular performs an extra check after each pass to verify the bindings did not change (the source of NG0100); it does not exist in production.

OnPush is the bridge to zoneless. Per the Angular team, components compatible with OnPush are mostly compatible with zoneless as well — they already tell Angular when they change.

🔥 Interview recall
  • Change detection re-evaluates template bindings and updates the DOM; cost = components checked.
  • zone.js triggers a pass after every async task (timers, network, events); zoneless needs an explicit notification.
  • Eager (old Default) checks everything; OnPush checks on input change, an event in the subtree, or an explicit mark.
  • OnPush compares inputs with Object.is; mutating an object does not trigger a check.
  • Zoneless is stable from v20.2 and default in v21+; the OnPush-as-default change is version-dependent.
  • NG0100 is a development-only second-pass check.
🎤 Say this in an interview
"Change detection is Angular re-checking template bindings. With zone.js it starts a pass after every asynchronous task; zoneless starts one only after an explicit notification like a signal read in a template. Eager checks every component, while OnPush skips subtrees whose inputs did not change, so I move components to OnPush and signals to cut the number of components checked."
⚠️ Common trap

Mutating an input object under OnPush. Angular compares references; nothing looks changed.

Calling expensive methods from a template. They run on every check of that component.
