📖 Why did this need to exist?

Page 1 introduced inputs and outputs in a picture. Real screens quickly need more: a card whose layout is fixed but whose content varies, a parent that must call a method on a child, two siblings that must stay in sync.

Choosing the wrong channel creates the classic Angular tangles: parents reaching into children, services used as global variables, outputs chained through five levels.

This reference page lists each channel, when to use it, and the signal-based APIs (input, output, model, viewChild, contentChild) that replace the decorator forms.

▾ Go one level deeper (60 seconds)

model(). A writable signal exposed as an input/output pair; the output name is the input name plus Change. Custom form controls should use a model input for their main value.

Queries. Query functions return signals that stay current. Content queries read from elements nested inside the component in the template where it is used; view queries read the component’s own template.

Templates as parameters. ng-template lets a parent pass a fragment (for example a row template) to a component; its expressions run against the declaring component.

🔥 Interview recall
  • Down: input(); up: output(); both: model().
  • Projection: <ng-content select=…> slots; one unselected slot catches the rest; not inside @if/@for/@switch.
  • View queries read your own template; content queries read projected content (direct children by default).
  • Query results are signals; they are not ready in the constructor.
  • Unrelated components share a root-provided service with signals.
  • Avoid parents reaching into children’s DOM.
🎤 Say this in an interview
"Data flows down through input signals and events flow up through outputs, with model for two-way bindings. For reusable layouts I use content projection with named slots, queries when a component must read what it contains, and a root-provided service with signals when the components are not parent and child."
⚠️ Common trap

Boolean-input explosions. Ten flags on a Card mean it wants projection.

Using a service as a global variable bag. Prefer inputs and outputs when there is a parent–child relationship.
