Concept 3 of 12 · 🅰️ The update model

Tell Angular what you use, and it checks only that.

How OnPush and signals cut the number of components checked, signal(), computed() and input signals in five lines, and a leaf-first migration path to zoneless.

❓ "What is OnPush change detection and how do signals relate to it?"
👁 See it first
🎯 OnPush tells Angular “only check me when something I use changed”; signals are how a component says exactly what it uses.
▶️ Watch it happen: only when something I use changed
📖 Why did this need to exist?

Page 2 showed the cost: Eager checks every component after every task. The fix is to make each component declare when it needs checking. OnPush is the declaration; it also marks a component dirty when its input changes, when an event fires inside it, or when you call markForCheck().

But OnPush alone puts a burden on you: you must remember to notify Angular when state changes outside those cases. Signals remove the burden. A signal read in a template is the notification — when the value changes, exactly the components that read it are scheduled.

Together they are also the bridge to zoneless Angular: components that are OnPush-compatible are mostly zoneless-compatible too.

🪜 The migration staircase
📚 Signals in five lines
APIWhat it isUse it for
signal(initial)A writable value; read by calling it, change with .set() or .update()Local state: query = signal('')
computed(() => …)A read-only value derived from other signals; evaluated lazily on first read, cached until a dependency changesDerived data: filtered list, total price
input() / input.required()An input exposed as a read-only signalData from a parent (page 1)
model()A writable input with a matching outputTwo-way binding
effect(() => …)Runs when the signals it reads change; asynchronously, during change detectionLast resort: logging, syncing with non-signal APIs (page 5)

Read a signal by calling it — query(). Only the signals actually read while a computed or effect runs are its dependencies. Prefer computed() to an effect that copies state into other state — the docs warn that this can cause ExpressionChangedAfterItHasBeenChecked errors and circular updates.

🧪 OnPush lab · from 504 checks to 3
// Before — Eager card, a method called from the template, mutable state in the parent
@Component({ selector: 'app-product-card', template: `<h3>{{ label() }}</h3>` })

// After — OnPush card + signal input + computed
@Component({
  selector: 'app-product-card',
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `<h3>{{ label() }}</h3>`,
})
export class ProductCard {
  product = input.required<Product>();
  label = computed(() => this.product().name.toUpperCase());   // cached until product changes
}

// App: the search text is a signal; ProductList reads it
query = signal('');
<app-product-list [query]="query()" />

▾ Go one level deeper (60 seconds)

What marks a component dirty (OnPush). A changed input from a template binding, an event listener in it or a descendant, an explicit markForCheck() (the async pipe does this), or a signal it reads changing.

Inputs are compared with Object.is in current versions, so pass a new object or array when data changes.

Signal inputs are read-only signals, so computed() can derive from them and the template re-checks only when they change.

🔥 Interview recall
  • OnPush: check a component only when an input changes, an event fires in its subtree, it is marked, or a signal it reads changes.
  • A signal read in a template is the notification — only its readers are scheduled.
  • computed() is lazy and cached; prefer it to an effect that copies state.
  • Update objects and arrays immutably; OnPush compares by reference.
  • Migrate leaf-first: OnPush on cards, then signals, then remove zone.js.
  • OnPush-compatible components are mostly zoneless-compatible.
🎤 Say this in an interview
"I make components OnPush and keep their state in signals, so Angular checks a component only when something it reads changes. Derived values use computed, updates are immutable, and effects are a last resort. That cuts a keystroke in our shop from checking every component to checking three, and it is also the path to running without zone.js."
⚠️ Common trap

Adding OnPush and then mutating. The component stops updating and people “fix” it with markForCheck everywhere.

Using effect() to copy one signal into another. Use computed().

📣 markForCheck()

Manually says “check me next pass” — a patch for state Angular cannot see.
