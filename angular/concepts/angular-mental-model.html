📖 Why did this need to exist?

React gives you a rendering library and lets you choose the rest. Angular is a full framework: components, templates, dependency injection, a router, forms and an HTTP client come in one box, with one way to do each. That is why large teams like it — and why there is more to learn up front.

Everything in this lab hangs off one picture: the component tree. Bindings move data down and events up; services (page 7) are shared through injection. Page 2 asks the next question: when something changes, how does Angular find out which parts of the tree to update?

We use the same practice app, ShopUI, as the React lab — so you can compare how each framework answers the same problem.

▾ Go one level deeper (60 seconds)

Standalone. By default Angular components are standalone, so you add them directly to another component’s imports. Before version 19 the standalone option defaulted to false and apps were built from NgModules.

The providers. app.config.ts exports an ApplicationConfig whose providers array holds things like provideRouter(routes) and provideHttpClient(). Environment providers like these belong in the application (or a route’s) providers, not in a component’s.

Versions. This lab teaches modern Angular (signals, built-in control flow, zoneless by default in new apps). Where an older codebase differs, pages say so.

🔥 Interview recall
  • An Angular component = a class with @Component (selector, template, imports) + inputs and outputs.
  • Bindings: {{ }} text, [prop] down, (event) up, [(x)] both ways (with model()).
  • Components are standalone by default (v19+); template dependencies go in imports.
  • bootstrapApplication(App, appConfig) starts the app; providers live in app.config.ts.
  • Read signals by calling them: name().
  • ShopUI = 504 components; page 2 asks how Angular finds what changed.
🎤 Say this in an interview
"An Angular app is a tree of standalone components. Each has a class for state and a template for markup, and bindings connect them: interpolation for text, property binding to pass data down into input signals, event binding to receive output events, and model for two-way. Angular is a full framework, so routing, forms, HTTP and dependency injection come built in."
⚠️ Common trap

Forgetting to call a signal in a template. product is the signal object; product() is its value.

Following an NgModule-era tutorial in a standalone codebase. The structure and the imports differ.
