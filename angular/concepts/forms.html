Template-driven, reactive and signal forms compared; the value/validity/touched state every control tracks; and the zoneless caveat.

❓ "What is the difference between template-driven and reactive forms in Angular?"
👁 See it first
🎯 A form is a model plus rules plus state: what the values are, whether they are valid, and whether the user has touched them. Pick the system that makes those three explicit.
▶️ Watch it happen: model, rules, state
📖 Why did this need to exist?

Page 7 gave you shared services. The most common thing those services feed is a form — and the ShopUI checkout has about 12 fields with validation. Forms are where change detection, state and validation all meet.

Angular is unusual in offering three built-in systems. Choosing wrongly costs you: template-driven forms get hard to test and extend; heavy reactive forms need discipline about subscriptions (page 6); signal forms are the newest, so check which Angular version your project is on.

This page compares them, shows the state every control tracks, and covers the zoneless caveat that matters for change detection (page 2).

Versions. The signal-forms overview says it requires Angular v21 or higher; one comparison page lists it as stable from v22 and the API page for compatForm says stable since v22.0 — always check the label for your version. Migration is supported both ways: wrap an existing reactive control with compatForm (top-down) or use a signal form control inside a reactive group (bottom-up).

🧭 The state every control tracks
🧪 Forms lab · the 12-field checkout
// Reactive — the model and the rules live in the class
form = inject(FormBuilder).group({
  email:   ['', [Validators.required, Validators.email]],
  address: ['', Validators.required],
  phones:  inject(FormBuilder).array(['']),          // FormArray: add/remove rows
});

// Template: bind and show errors only after the user touched the field
<input formControlName="email" />
@if (form.controls.email.touched && form.controls.email.invalid) { <p>Enter a valid email.</p> }

▾ Go one level deeper (60 seconds)

Reactive building blocks. FormControl tracks the value and validation status of one control; FormGroup does the same for a collection; FormArray for an array of controls.

Signal-form validation. A schema function passed as the second argument to form() attaches rules to field paths; per-field state is read through signals, and Standard Schema libraries such as Zod or Valibot can be used through validateStandardSchema.

Custom controls (a date picker) should use a model() input for their primary value. The validation deep dive covers async validators and FormArray in detail.

🔥 Interview recall
  • Three systems: template-driven (small), reactive (complex, testable), signal forms (newest; check the version).
  • Reactive: FormControl, FormGroup, FormArray, validator functions.
  • Every control tracks value, validity/errors and interaction (touched, dirty).
  • Show an error only when invalid and touched.
  • Zoneless: reactive-form model updates do not schedule change detection by themselves.
  • End valueChanges subscriptions with takeUntilDestroyed().
🎤 Say this in an interview
"For small forms template-driven is fine; for complex, testable forms I use reactive forms with a FormGroup, validator functions and a FormArray for repeating rows; signal forms are the newer signal-based option and I check which Angular version we are on. I show errors only when a control is invalid and touched, and in zoneless apps I make sure form updates notify Angular."
⚠️ Common trap

Showing errors from validity alone. A fresh form looks broken.

Leaving valueChanges subscriptions open. The classic reactive-forms leak.

📋 Template-driven

Logic in the template via directives; simple, harder to test.

vs.
🧱 Reactive

Logic in the class via FormGroup and validator functions; explicit and scalable.
