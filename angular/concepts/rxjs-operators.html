📖 Why did this need to exist?

Page 6 introduced observables and the four flattening operators. In real code the same handful appears again and again: debounce, distinct, switchMap, combineLatest, catchError, takeUntil. Learning them as a decision map beats memorising the API list.

The second thing to learn is when to leave RxJS: for a current value a signal is simpler (page 5). Operators earn their place when time, cancellation or combination of streams matters.

This reference page maps each question to an operator, with the one-line behaviour from the RxJS docs.

📚 The operators you actually use
QuestionOperatorWhat it does (RxJS docs)

Latest of several streamscombineLatestEmits when any input emits (after all have emitted once)

Sharing. A cold observable (such as an HttpClient call) starts per subscription; share / shareReplay let several subscribers use one source, and converting once with toSignal is often simpler.

🔗 combineLatest or forkJoin?
🧪 Operators lab · the product search pipeline
products = toSignal(
  combineLatest([toObservable(this.query), toObservable(this.sort)]).pipe(
    debounceTime(300),
    distinctUntilChanged(([q1, s1], [q2, s2]) => q1 === q2 && s1 === s2),
    switchMap(([q, s]) => this.http.get<Product[]>(`/api/products?q=${q}&sort=${s}`).pipe(
      catchError(() => of([] as Product[])),                   // a fallback value, not EMPTY
    )),
  ),
  { initialValue: [] },
);

Illustrative sketch; 300 ms is a teaching value. catchError sits inside the inner observable so one failed request does not end the whole stream.

▾ Go one level deeper (60 seconds)

Deprecations. The array-argument signatures of forkJoin and combineLatest (many arguments) were deprecated in RxJS 6.5; pass an array or an object instead.

Not swallowing. Replacing an error with EMPTY in an HTTP interceptor or rxResource can finish with no value and no error; return a fallback value or let the error propagate (HTTP dive).

Signals first. If you only need the current value of a combination, computed() over signals is simpler than combineLatest.

🔥 Interview recall
  • Choose by question: time (debounceTime), repeats (distinctUntilChanged), request per event (flattening), combine (combineLatest/forkJoin), errors (catchError), end (takeUntil).
  • combineLatest = ongoing streams; forkJoin = one-shot streams that complete.
  • Put catchError inside the inner observable; return a fallback value.
  • switchMap for search, exhaustMap for submit, concatMap for ordered, mergeMap for independent.
  • A cold observable starts per subscription; share it or convert once with toSignal.
  • For a plain current value, prefer computed() over combineLatest.
🎤 Say this in an interview
"I pick RxJS operators by the question: debounceTime and distinctUntilChanged for typing, a flattening operator for the request — switchMap for search, exhaustMap for submit — combineLatest for ongoing inputs and forkJoin for one-shot loads, catchError inside the inner observable, and takeUntilDestroyed to end the stream. For simple current values I use signals instead."
⚠️ Common trap

forkJoin on a stream that never completes. It never emits.

catchError on the outer stream. The first error ends the pipeline.

🔗 combineLatest

Emits whenever any input changes; needs every input to have emitted once.

vs.
📦 forkJoin

Emits once, after all inputs complete.
