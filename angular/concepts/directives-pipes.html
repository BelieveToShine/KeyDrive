❓ "What is the difference between a component, a directive and a pipe in Angular?"
👁 See it first
🎯 Component = new UI, directive = new behaviour on an existing element, pipe = a value formatted for display.
▶️ Watch it happen: three building blocks
📖 Why did this need to exist?

Page 4 used built-in control flow and built-in pipes. Real apps repeat the same small behaviours — autofocus, tooltips, “format this as money”, “click outside to close” — and copying them into every component is the next scatter after copying HTTP logic (HTTP dive).

Angular gives each repeated thing a home: directives for behaviour, pipes for formatting, and directive composition (hostDirectives) to build bigger behaviours from small ones.

This page shows how to write each, how host bindings work, and how composition keeps parent templates unchanged.

🎛️ Writing a directive
@Directive({
  selector: '[appHighlight]',                      // applied as an attribute
  host: { '[class.on]': 'active()', '(mouseenter)': 'active.set(true)', '(mouseleave)': 'active.set(false)' },
})
export class Highlight {
  active = signal(false);
  color = input('yellow', { alias: 'appHighlight' });   // one binding applies it and passes a value
}

<p [appHighlight]="'orange'">Hover me</p>

Illustrative sketch. The host property declares host bindings and event listeners; the docs prefer it to @HostBinding, which remains for backwards compatibility.

🔧 Writing a pipe
@Pipe({ name: 'price' })                           // pure by default
export class PricePipe implements PipeTransform {
  transform(cents: number, currency = 'USD'): string {
    return new Intl.NumberFormat('en', { style: 'currency', currency }).format(cents / 100);
  }
}

Illustrative sketch. A pure pipe runs only when its inputs change (page 4); pure: false makes it run every change-detection cycle — avoid unless absolutely necessary.

▾ Go one level deeper (60 seconds)

Host. A directive’s host property maps host bindings and events to class members; it is preferred over @HostBinding/@HostListener.

Directive inputs named like the selector let one binding both apply the directive and pass a value.

Pipes in classes. Pipes are classes with a transform method; you can also call that method from code when you need the formatted value there.

🔥 Interview recall
  • Component = template; directive = behaviour on an existing element; pipe = value formatting.
  • A directive is a class with @Directive({ selector }); host bindings and events go in the host property.
  • hostDirectives composes directives onto a component; inputs/outputs are exposed only if listed.
  • A custom pipe implements PipeTransform; pure by default.
  • NG8024 = conflicting aliases for a shared host-directive input.
  • Prefer computed() to a pipe for class-side derivation.
🎤 Say this in an interview
"I write a component when I need a template, an attribute directive when I need reusable behaviour on an existing element, and a pure pipe to format values. I use hostDirectives to compose behaviours onto a component without touching the parent template, and I avoid impure pipes."
⚠️ Common trap

An impure pipe for convenience. It runs on every check of every instance.

A component where a directive would do. You gain a wrapper element and lose flexibility.
