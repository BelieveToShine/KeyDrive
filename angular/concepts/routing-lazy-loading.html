The router decides what loads, when, and for whom.

Route config, loadComponent and loadChildren, preloading, the guard → resolver → activate order, and binding route params to inputs.

❓ "How does lazy loading work in Angular routing, and what is the order of guards and resolvers?"
👁 See it first
🎯 The router maps URLs to components — and decides when code and data are loaded. Lazy routes keep the first load small; guards and resolvers control who gets in and what is ready.
📖 Why did this need to exist?

Page 8 collected data in forms; real apps have many screens. Angular’s router is part of the framework, integrated with dependency injection (route providers), signals (route data as inputs) and the build (lazy chunks).

The same ideas appeared in the React lab (routing dive and bundles page): a URL tree, nested layouts, route-level code splitting. Angular gives you one official answer.

This page covers the route config, lazy loading with loadComponent / loadChildren, preloading, and a first look at guards and resolvers; the guards deep dive goes further.

🗺️ A route config
// app.routes.ts — provided with provideRouter(routes) in app.config.ts
export const routes: Routes = [
  { path: '', component: Home },
  { path: 'products/:id', component: ProductPage },             // :id → a route parameter
  { path: 'checkout', loadComponent: () => import('./checkout/checkout').then(m => m.Checkout),
    canActivate: [signedInGuard] },                         // lazy + guarded
  { path: 'admin', loadChildren: () => import('./admin/routes').then(m => m.adminRoutes) },
];

Illustrative sketch. provideRouter(routes, withComponentInputBinding()) would bind :id to a component input.

📋 Loading strategies
OptionWhat it doesUse it for
componentIncluded in the main bundleThe home page and the shell
loadComponentLoads one component’s JavaScript when its route becomes activeA single heavy screen (checkout)
loadChildrenLoads a set of child routes during route matchingA feature area (admin)
NoPreloading (default)Lazy chunks load only on navigationSmallest background traffic
withPreloading(PreloadAllModules)Loads all lazy routes right after the initial navigationFast later navigation on good networks
Custom PreloadingStrategyPreload only routes flagged, e.g. data: { preload: true }Preload checkout, not admin

Lazy loaders run in the route’s injection context, so they can call inject(). The preloader does not load routes protected by canLoad guards.

▾ Go one level deeper (60 seconds)

Guards are not security. They shape navigation in the browser; the server must still authorise every request.

Guard results. true continues, false cancels, a UrlTree (or RedirectCommand) cancels and starts a new navigation. canMatch returning false does not block navigation — the router tries the next matching route definition.

Where providers go. A route’s providers array creates an injector for that route’s subtree (page 7).

🔥 Interview recall
  • Routes map URLs to components; provideRouter(routes) goes in the application config.
  • loadComponent / loadChildren split code per route; the default is no preloading.
  • Order: match → guards → resolvers → activate.
  • Guards return true, false or a UrlTree; redirect with a UrlTree.
  • withComponentInputBinding() turns route params and data into inputs.
  • Guards are UX, not security.
🎤 Say this in an interview
"I define routes in a config, lazy-load heavy areas with loadComponent and loadChildren so the first bundle stays small, and optionally preload what users are likely to visit next. Navigation runs guards and then resolvers before activating the component; guards redirect by returning a UrlTree, route params become inputs with component input binding, and real access control is enforced on the server."
⚠️ Common trap

Importing a lazy feature’s code from an eager file. The bundler pulls it back into the main bundle.

Returning false from a guard and then navigating in code. Return a UrlTree instead.

🔒 canActivate

Decides whether to enter a route that matched.

vs.
🧭 canMatch

Decides whether the route definition applies at all; false means try the next one.
