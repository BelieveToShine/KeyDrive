Pick a database by the shape of your data and the questions you will ask — not by what is popular.

Tables that relate to each other, flexible JSON items at world scale, and plain files all need different homes. Azure has a family of databases for this. Learn the map, then learn when each one wins.

❓ "When would you choose Azure SQL, PostgreSQL/MySQL or Cosmos DB for a new application?"
👁 See it first
🎯 Pick a database by the shape of your data and the questions you will ask — not by what is popular. Related tables → Azure SQL (or Postgres/MySQL). Flexible items at world scale → Cosmos DB.
▶️ Watch it happen: shape of the data decides
📖 Why did this need to exist?

Storage keeps files and simple records safe. But imagine this question: "Show customer 42's orders from last month over $100 — and when they buy, reduce the stock and save the order, or do neither." A storage account cannot search across records, join related data, or promise that two changes happen together.

A database adds exactly those three things: fast queries (indexes), relationships between data, and transactions — all-or-nothing changes. Azure offers several databases because data comes in different shapes, and forcing every shape into one engine means paying for it later in speed, cost or complexity.

🧰 The Azure database family

🗄️ Azure SQL Database

the fully managed SQL Server engine, for new cloud apps✅ Pick it when
  • A new app with related tables
  • You want Microsoft to patch, back up and run it
  • Spiky or idle workloads (serverless option can pause when idle)
  • Very large databases (Hyperscale tier)
⛔ Look elsewhere when
  • You need instance-level SQL Server features → Managed Instance
  • You need the operating system itself → SQL on a VM

🏢 SQL Managed Instance

nearly all SQL Server features, still managed✅ Pick it when
  • Moving an existing SQL Server app with minimal changes
  • You rely on SQL Agent, linked servers, cross-database queries or CLR
⛔ Look elsewhere when
  • A brand-new app that needs none of those → SQL Database is simpler

🖥️ SQL Server on an Azure VM

your own SQL Server, running on a virtual machine✅ Pick it when
  • You need access to the operating system or file system
  • You must stay on one exact SQL Server version
  • You already own licenses you want to reuse
⛔ Look elsewhere when
  • You do not want to patch and look after a VM → use a managed option

🐘 PostgreSQL / MySQL Flexible Server

managed open-source relational databases✅ Pick it when
  • Your app is built for PostgreSQL or MySQL
  • You want open-source tools and extensions
  • You want a managed service without rewriting the app
⛔ Look elsewhere when
  • You are an SQL Server shop with T-SQL code → Azure SQL
  • You need flexible JSON at world scale → Cosmos DB

🌍 Azure Cosmos DB

a globally distributed NoSQL database✅ Pick it when
  • Flexible JSON items and a schema that keeps changing
  • Users all over the world who need fast reads and writes
  • Huge scale by spreading data over partitions
⛔ Look elsewhere when
  • Many joins and strict relationships between tables → relational
  • You cannot choose a good partition key yet

🛒
Online shop orders

Customers, orders and stock must stay consistent. Money is involved.

→ Azure SQL Database
🏭
Old ERP on SQL Server

Uses SQL Agent jobs and cross-database queries. Rewriting it is not possible this year.

→ SQL Managed Instance

App built on PostgreSQL

The team already knows Postgres and uses its extensions.

→ PostgreSQL Flexible Server

Game player profiles

Millions of players worldwide, profile read on every login, schema changes each season.

→ Cosmos DB

Product catalog

Shoes have a size; laptops have RAM. Every product has different attributes.

→ Cosmos DB (or SQL with JSON)
🏦
Bank ledger

Every transfer must be exact, auditable and all-or-nothing across accounts.

→ Azure SQL Database

Cosmos DB vs Azure SQL

The two you will be asked about most: side-by-side strengths and weaknesses, partition keys, request units, consistency levels and when to use both.

Open the deep dive →
▾ Go one level deeper (60 seconds)

Two ways to buy Azure SQL. The vCore model lets you pick compute and storage separately. The DTU model bundles them into simple packages. The serverless compute tier (vCore only) scales with load and can pause when idle, so you pay for storage only while it is paused.

Hyperscale is the service tier built for very large databases and fast scaling of storage and read copies.

PostgreSQL and MySQL: use Flexible Server. The older PostgreSQL "Single Server" has been retired, so new work should never start on it.

Cosmos DB has several APIs — NoSQL (its native one, recommended for new apps), MongoDB, Cassandra, Gremlin (graph) and Table — so you can often keep the tools you already know.

🔥 Interview recall
  • Choose by data shape and question shape: related tables → relational; flexible items at global scale → Cosmos DB; plain files → Storage.
  • Azure SQL family: SQL Database (most managed, new apps) → Managed Instance (SQL Server features, easy migration) → SQL Server on a VM (full OS control).
  • PostgreSQL / MySQL → use Flexible Server.
  • Relational scales mostly up, with read copies. Cosmos DB scales out by partition key, and can replicate to other regions.
  • A database adds queries, relationships and transactions — the things Storage cannot do.
🎤 Say this in an interview
"I choose a database by the shape of the data and the queries. For related tables and transactions I start with Azure SQL Database, move to Managed Instance if I need instance-level SQL Server features, and only use SQL on a VM when I need the OS. For open-source apps I use PostgreSQL or MySQL Flexible Server. For flexible JSON data that must be fast worldwide I use Cosmos DB, where the partition key is the key design decision."
⚠️ Common trap

"NoSQL" does not mean "better" or "faster for everything". Cosmos DB is excellent when your queries match your partition key, and painful when they do not. Relational databases are not "old" — for related data and transactions they are still the right default.

Also watch the names: Azure SQL Database is one product, Azure SQL is the whole family, and Azure Database for PostgreSQL is a different service again.

🗄️ Azure SQL Database

Fully managed. You get a database, not a server. Best for new apps.

vs.
🏢 SQL Managed Instance

A whole managed SQL Server instance, with features like SQL Agent. Best for moving existing apps with few changes.
