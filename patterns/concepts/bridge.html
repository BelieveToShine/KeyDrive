Remote and device: let two lists grow separately.

The Bridge pattern: split an abstraction from its implementation so they vary independently.

❓ "What is the Bridge pattern?"
👁 See it first
🎯 Separate “what it is” from “how it is done” into two hierarchies connected by a bridge, so each changes alone.
🌍 In real life

🔌 A universal remote and a device: you can buy a new remote without buying a new TV, and a new TV works with the same remote buttons. The “has a” link between them is the bridge.

refactoring.guru: Bridge lets you split a large class or a set of closely related classes into two separate hierarchies — abstraction and implementation — that can be developed independently.

🔧 The pattern fixes it
🧪 Tiny code
interface IDevice { void On(); void Off(); }
class Tv    : IDevice { public void On() { } public void Off() { } }
class Radio : IDevice { public void On() { } public void Off() { } }

class Remote(IDevice device)                   // the bridge: a Remote HAS a Device
{
    public virtual void Power() => device.On();
}
class AdvancedRemote(IDevice device) : Remote(device) { public void Mute() { } }

new AdvancedRemote(new Tv()).Power();

This is composition over inheritance applied to two dimensions of change.

🎯 Spot it: is the pattern a good fit?
▾ Two independent dimensions that both keep growing

✅ Good fit. Bridge keeps the sizes additive.

▾ Only one dimension varies

❌ Overkill. Plain polymorphism is enough.

▾ Platform-specific code under a cross-platform API

✅ Good fit. A classic use.

▾ A one-off pair of classes

❌ Overkill. Do not build a bridge for a single case.

👀 How to spot the need in your own code
If you see…Do this
Class names like BasicTvRemote, AdvancedRadioRemoteTwo dimensions in one hierarchy.
🔥 Interview recall
  • Bridge = abstraction and implementation as two hierarchies linked by composition.
  • Avoids class explosion (m × n).
  • Planned up front; Adapter is applied afterwards.
🎤 Say this in an interview
"Bridge splits an abstraction from its implementation into two hierarchies connected by composition, so remotes and devices can grow independently and the number of classes adds instead of multiplying. Unlike Adapter, which fixes a mismatch after the fact, Bridge is designed in advance."
⚠️ Common trap

Confusing Bridge and Adapter. Bridge is planned; Adapter fixes a mismatch.
