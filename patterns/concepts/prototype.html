A photocopy of a template: copy it, then tweak it.

The Prototype pattern: make a new object by cloning an existing one.

❓ "What is the Prototype pattern and when is cloning better than constructing?"
👁 See it first
🎯 Make a new object by copying an existing, ready-made one, then change what differs.
🌍 In real life

🧾 An office keeps a template form. Nobody redraws it every time; they photocopy it and fill in the blanks.

refactoring.guru: Prototype lets you copy existing objects without making your code dependent on their classes; the cloning process is delegated to the objects being cloned.

🔧 The pattern fixes it
🧪 Tiny code
class Report
{
    public string Font = "Arial"; public string Header = "ACME"; public DateOnly Date;
    public Report Clone() => (Report)MemberwiseClone();       // shallow copy of the fields
}

var template = new Report { Font = "Calibri", Header = "ACME Ltd" };
var tuesday = template.Clone(); tuesday.Date = new DateOnly(2026, 10, 14);

MemberwiseClone copies fields shallowly; objects holding other objects (like lists) need a deep copy. C# records offer with expressions for a similar effect.

🎯 Spot it: is the pattern a good fit?
▾ Objects that are expensive or fiddly to set up, and many are almost the same

✅ Good fit. Clone a prepared one.

▾ Simple objects with two fields

❌ Overkill. Just construct them.

▾ A copy must not share inner lists with the original

✅ Good fit. Remember deep versus shallow copies.

▾ You want the copy to stay linked to the original

❌ Overkill. Then it is a reference, not a clone.

👀 How to spot the need in your own code
If you see…Do this
Repeated blocks of property assignments building “almost the same” objectsClone a template.
🔥 Interview recall
  • Prototype = new objects by cloning existing ones.
  • Shallow versus deep copy matters.
  • Handy for presets and templates.
🎤 Say this in an interview
"Prototype makes new objects by cloning a prepared one and changing what differs, like photocopying a template form. I watch for shallow versus deep copies, and in modern C# a record with a with-expression often does the job."
⚠️ Common trap

Shallow copy surprises. Both copies share the same inner list.
