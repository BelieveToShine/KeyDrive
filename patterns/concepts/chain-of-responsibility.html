Concept 15 of 24 · 💬 Behavioral

Customer-support escalation: pass it along until someone handles it.

The Chain of Responsibility pattern with support levels: each link handles a request or passes it on, so rules stay separate and easy to rearrange.

❓ "What is the Chain of Responsibility pattern and where do you see it in ASP.NET Core?"
👁 See it first
🎯 Line up handlers; each one either handles the request or passes it to the next.
🌍 In real life

📞 In a support centre, a small refund is handled by the agent. A bigger one is passed to a supervisor, a huge one to a manager. Nobody needs the whole rulebook: each person knows their own limit and who is next.

refactoring.guru: Chain of Responsibility lets you pass requests along a chain of handlers; upon receiving a request, each handler decides either to process it or to pass it to the next handler in the chain.

⛓️ The fix: a chain

🧪 Tiny code
abstract class Handler
{
    private Handler? _next;
    public Handler SetNext(Handler next) { _next = next; return next; }
    public virtual string Handle(int amount) => _next?.Handle(amount) ?? "nobody can handle it";
}
class Agent : Handler      { public override string Handle(int a) => a <= 50  ? "Agent handled it"      : base.Handle(a); }
class Supervisor : Handler { public override string Handle(int a) => a <= 500 ? "Supervisor handled it" : base.Handle(a); }
class Manager : Handler    { public override string Handle(int a) => "Manager handled it"; }

var agent = new Agent(); agent.SetNext(new Supervisor()).SetNext(new Manager());
Console.WriteLine(agent.Handle(800));      // Manager handled it

Each link decides: handle, or call base.Handle to pass on.

🎯 Spot it: is the pattern a good fit?
▾ A request may be handled by one of several handlers, decided at run time

✅ Good fit. Chain them.

▾ You always know exactly who must handle it

❌ Overkill. Call them directly.

▾ Steps should be rearrangeable or optional

✅ Good fit. Chains are easy to reorder.

▾ Every request must be handled by someone

❌ Overkill. A chain can end with nobody handling it — make sure you plan for that.

👀 How to spot the need in your own code
If you see…Do this
A long if/else deciding who handles somethingTurn each branch into a handler.
Pipelines where each step may stop processingThat is a chain.
🔥 Interview recall
  • Chain of Responsibility = handlers in a line; each handles or passes on.
  • The sender does not know who will handle it.
  • ASP.NET Core middleware is a chain.
  • Plan for “nobody handled it”.
🎤 Say this in an interview
"Chain of Responsibility passes a request along a line of handlers; each either handles it or passes it to the next. A support escalation is the picture, and ASP.NET Core middleware is the .NET example. It keeps each rule separate and the chain easy to rearrange, but I plan for the case where nobody handles the request."
⚠️ Common trap

Request falls off the end. Add a default handler.

Long chains are hard to debug. Log which link handled it.
