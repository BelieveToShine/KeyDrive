Twelve small cases: name the pain, pick the pattern.

A practice ward for the whole lab: symptom, evidence, your pattern, then reveal — with an answer key back to each page.

❓ "Here is a design problem. Which pattern would you try, and why?"
👁 See it first
🎯 You have seen creational, structural, behavioral and whole-system patterns. This is the practice ward: symptom → evidence → pattern → why → where to review.
🧭 How to decide

Ask in this order: what hurts? → which family of question is it (making, shaping, behaving, or whole system)? → which pattern removes exactly that pain? → is the next change cheaper?

🩺 Case 1

Adding a pizza type edits three screens

Symptom. Each screen has its own if/else that creates the pizza class.

Evidence.

  • The same if type == … appears in 3 files.

Your move: which pattern would you try?

▾ Reveal the answer

Diagnosis. Creation logic is copied everywhere.

Pattern. One Factory decides; screens ask it.

📖 Where to review: page 2.

🩺 Case 2

A constructor with eight unnamed values

Symptom. new Burger("sesame","beef",true,false,true,"none",false,true)

Evidence.

  • Nobody remembers what the third true means.

Your move: which pattern would you try?

▾ Reveal the answer

Diagnosis. A telescoping constructor.

Pattern. Builder with named steps and defaults.

📖 Where to review: page 3.

🩺 Case 3

The payment vendor’s types are everywhere

Symptom. Switching vendors would touch 30 files.

Evidence.

  • VendorClient and VendorResponse appear across the code.

Your move: which pattern would you try?

▾ Reveal the answer

Diagnosis. A foreign API shape leaks through the app.

Pattern. Adapter behind your own IPaymentGateway.

📖 Where to review: page 5.

🩺 Case 4

Logging code is pasted into every repository method

Symptom. Every method starts with the same three log lines.

Evidence.

  • 10 repositories, 40 methods, same lines.

Your move: which pattern would you try?

▾ Reveal the answer

Diagnosis. Cross-cutting behaviour mixed into the class.

Pattern. Decorator that logs and delegates.

📖 Where to review: page 6.

🩺 Case 5

Callers must call five classes in order

Symptom. Booking an evening = taxi, restaurant, tickets, in the right order.

Evidence.

  • The same 5-call sequence is copied in four places.

Your move: which pattern would you try?

▾ Reveal the answer

Diagnosis. A complex subsystem exposed to everyone.

Pattern. Facade with one Plan() method.

📖 Where to review: page 7.

🩺 Case 6

A new customer type means opening the pricing switch

Symptom. The discount method grows with every type.

Evidence.

  • One method, six branches, edited monthly.

Your move: which pattern would you try?

▾ Reveal the answer

Diagnosis. Several interchangeable ways inside one class.

Pattern. Strategy per way, plugged in.

📖 Where to review: page 10.

🩺 Case 7

The channel calls every fan by name

Symptom. A new fan means editing the channel.

Evidence.

  • Channel code lists Asha, Ben, Chen…

Your move: which pattern would you try?

▾ Reveal the answer

Diagnosis. Publisher knows its listeners.

Pattern. Observer: subscribe and notify the list.

📖 Where to review: page 11.

🩺 Case 8

Users want undo and a history

Symptom. Actions run directly and leave no trace.

Evidence.

  • Buttons call lamp.On() directly.

Your move: which pattern would you try?

▾ Reveal the answer

Diagnosis. Requests vanish after being made.

Pattern. Command objects with Execute/Undo and a history.

📖 Where to review: page 12.

🩺 Case 9

Everything freezes when one service is slow

Symptom. A slow dependency makes every caller wait 30 seconds.

Evidence.

  • Retries pile up; threads are exhausted.

Your move: which pattern would you try?

▾ Reveal the answer

Diagnosis. Hammering a failing dependency (retry storm).

Pattern. Retry with backoff + Circuit Breaker + fallback.

📖 Where to review: page 20.

🩺 Case 10

A booking leaves a flight and hotel but no car

Symptom. The third service failed after two succeeded.

Evidence.

  • Three services, three databases, no common rollback.

Your move: which pattern would you try?

▾ Reveal the answer

Diagnosis. No way to undo across services.

Pattern. Saga with compensating steps.

📖 Where to review: page 19.

🩺 Case 11

The same product query hits the database 1,000 times a minute

Symptom. The database is busy; pages are slow.

Evidence.

  • Same query, same answer, repeated.

Your move: which pattern would you try?

▾ Reveal the answer

Diagnosis. Repeated slow work.

Pattern. Cache-Aside with expiry and invalidation.

📖 Where to review: page 21.

🩺 Case 12

A two-year rewrite plan with one launch date

Symptom. Nothing new ships until the end.

Evidence.

  • Big-bang switch planned for next year.

Your move: which pattern would you try?

▾ Reveal the answer

Diagnosis. High-risk all-at-once replacement.

Pattern. Strangler Fig: route features over one by one.

📖 Where to review: page 22.

🔥 Interview recall
  • Method: what hurts → which family → which pattern → is the next change cheaper?
  • Families: creating, shaping, behaving, whole systems.
  • Similar symptoms, different patterns: read the evidence.
  • Prefer the smallest pattern.
🎤 Say this in an interview
"I read a design problem as a symptom with evidence, work out whether it is about making objects, shaping structure, behaviour, or a whole system, and pick the smallest pattern that removes exactly that pain — then check the next change really is cheaper."
⚠️ Common trap

Picking the pattern you learned last. Read the evidence.

Stopping at the diagram. Check it removed the pain.

📚 Knowing patterns

You can recite names and diagrams.

🩺 Using patterns
