The fuse box: stop hammering something that is broken.

The Retry and Circuit Breaker patterns: handle small hiccups by trying again and big outages by failing fast.

❓ "What is the Circuit Breaker pattern and how does it work with Retry?"
👁 See it first
🎯 Retry short hiccups, but stop calling something that is clearly down — fail fast, then test gently if it has recovered.
🌍 In real life

🔌 A fuse box in your home cuts the power when something goes wrong, so one broken appliance does not burn the house. After you fix it, you flip it back on.

The Azure Architecture Center describes Retry as handling transient faults by retrying in a controlled way, and Circuit Breaker as preventing continuous requests to a malfunctioning dependency; they are often used together.

🧪 Tiny code
// Sketch of the idea (libraries such as Polly implement this properly)
class Breaker
{
    private int _fails; private DateTime _openUntil = DateTime.MinValue;
    public string Call(Func<string> action)
    {
        if (DateTime.UtcNow < _openUntil) return "service busy — try later";   // OPEN: fail fast
        try { var r = action(); _fails = 0; return r; }                         // CLOSED / HALF-OPEN success
        catch { if (++_fails >= 3) _openUntil = DateTime.UtcNow.AddSeconds(30); return "error"; }
    }
}

In real .NET apps use a tested library (Polly, or the resilience support in Microsoft.Extensions) instead of hand-rolling this.

🎯 Spot it: is the pattern a good fit?
▾ A call that fails now and then for a split second

✅ Good idea. Retry with backoff.

▾ A service that is down for ten minutes

✅ Good idea. A breaker stops the pile-up.

▾ Retrying a payment that may already have gone through

❌ Dangerous. Dangerous: make the operation idempotent first.

▾ Retrying forever with no wait

❌ Dangerous. That causes a “retry storm”; bound and back off.

👀 How to spot the need in your own code
If you see…Do this
A while(true) retry loopUse a bounded, backed-off retry.
Timeouts piling up when a dependency is slowAdd a circuit breaker and a fallback.
🔥 Interview recall
  • Retry = try again for transient faults, with a limit and backoff.
  • Circuit Breaker = after enough failures, fail fast; probe in half-open; close when healthy.
  • States: closed, open, half-open.
  • Operations must be idempotent to be safely retried.
🎤 Say this in an interview
"Retry handles short transient faults by trying again with a limit and backoff. A Circuit Breaker stops calling a dependency that is clearly failing: it opens after enough failures, fails fast, then half-opens to test recovery. I use both, make retried operations idempotent, and rely on a library like Polly."
⚠️ Common trap

Retry storms. Many callers retrying together make an outage worse.

Retrying non-idempotent calls (charging a card twice).
