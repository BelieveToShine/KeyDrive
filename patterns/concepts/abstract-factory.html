Matching sets: ask one factory for the whole family.

The Abstract Factory pattern with a dark and a light theme: create related objects that always match.

❓ "What is the Abstract Factory pattern and how does it differ from Factory Method?"
👁 See it first
🎯 Create whole families of related objects through one factory, so the pieces always match.
🌍 In real life

🛋️ A furniture shop sells a “Modern” set and a “Classic” set. You do not want a modern chair with a classic table: you pick a set.

refactoring.guru: Abstract Factory lets you produce families of related objects without specifying their concrete classes.

🔧 The pattern fixes it
🧪 Tiny code
interface IButton { } interface ICheckbox { }
interface IThemeFactory { IButton CreateButton(); ICheckbox CreateCheckbox(); }

class DarkFactory  : IThemeFactory { public IButton CreateButton() => new DarkButton();  public ICheckbox CreateCheckbox() => new DarkCheckbox(); }
class LightFactory : IThemeFactory { public IButton CreateButton() => new LightButton(); public ICheckbox CreateCheckbox() => new LightCheckbox(); }

void BuildScreen(IThemeFactory theme) { var b = theme.CreateButton(); var c = theme.CreateCheckbox(); }   // always a matching pair

Factory Method creates one product; Abstract Factory creates a family.

🎯 Spot it: is the pattern a good fit?
▾ Several related objects that must belong to the same family (themes, database providers)

✅ Good fit. One factory per family.

▾ A single product with no family

❌ Overkill. A plain Factory is enough.

▾ Adding a new product to every family later

❌ Overkill. You must change every factory: the pattern is easier for adding families than products.

▾ Switching a whole look or provider at startup

✅ Good fit. Swap the factory.

👀 How to spot the need in your own code
If you see…Do this
Parallel hierarchies: DarkButton/LightButton, DarkCheckbox/LightCheckboxUse one factory per family.
🔥 Interview recall
  • Abstract Factory = an interface for creating families of related objects.
  • Ensures matching pieces.
  • Easy to add families; harder to add new product types.
🎤 Say this in an interview
"Abstract Factory creates whole families of related objects through one interface, so a dark-theme factory always gives a matching button and checkbox. Swapping the factory swaps the family, though adding a new kind of product means touching every factory."
⚠️ Common trap

Confusing it with Factory Method. One product versus a family.
