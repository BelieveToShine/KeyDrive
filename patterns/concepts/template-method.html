Concept 14 of 24 · 💬 Behavioral

Making tea or coffee: the recipe is fixed, two steps change.

The Template Method pattern with a drink recipe: write the shared steps once in a base class and let subclasses fill in the different ones.

❓ "What is the Template Method pattern?"
👁 See it first
🎯 Write the fixed recipe once in a base class, and let subclasses fill in only the steps that differ.
🌍 In real life

🍵 Tea and coffee follow the same recipe: boil, brew, pour, add. The skeleton is the same; only the middle steps change.

refactoring.guru: Template Method defines the skeleton of an algorithm in the superclass but lets subclasses override specific steps without changing the structure.

📋 The fix: a recipe skeleton
🎭 Who is who
Role in the patternIn our storyIn code
Template methodthe recipeMake() (not overridden)
Fixed stepsboil, pourprivate methods in the base class
Hook stepsbrew, add extrasabstract Brew(), AddExtras()
🧪 Tiny code
abstract class Drink
{
    public void Make()          // the fixed recipe
    {
        BoilWater();
        Brew();                 // differs
        Pour();
        AddExtras();            // differs
    }
    private void BoilWater() { }
    private void Pour() { }
    protected abstract void Brew();
    protected abstract void AddExtras();
}
class Tea    : Drink { protected override void Brew() { /* steep */ } protected override void AddExtras() { /* lemon */ } }
class Coffee : Drink { protected override void Brew() { /* brew */  } protected override void AddExtras() { /* milk  */ } }

Template Method uses inheritance. If you prefer composition, pass the changing steps in as strategies — see Strategy.

🎯 Spot it: is the pattern a good fit?
▾ Two processes with the same sequence and a few different steps

✅ Good fit. Exactly the pattern.

▾ Processes that share nothing

❌ Overkill. No skeleton to share.

▾ You want to avoid inheritance

❌ Overkill. Use Strategy / pass in the steps instead.

▾ The steps’ order must not be changed by subclasses

✅ Good fit. The base class owns the order.

👀 How to spot the need in your own code
If you see…Do this
Two classes with near-identical methods that differ in a few linesExtract the skeleton.
Copy-pasted steps that drift apartShare them in a base class.
🔥 Interview recall
  • Template Method = the base class defines the algorithm skeleton; subclasses override specific steps.
  • The order is fixed in the base class.
  • Uses inheritance; Strategy is the composition alternative.
  • Keep the number of overridable steps small.
🎤 Say this in an interview
"Template Method defines the skeleton of an algorithm in a base class and lets subclasses override specific steps without changing the order, like the same tea and coffee recipe with different brew and extras. It removes duplication, though it uses inheritance, so I sometimes pass steps in as strategies instead."
⚠️ Common trap

Too many hooks. Subclasses become hard to follow.

Subclass breaks the recipe. Make the template method non-overridable.
