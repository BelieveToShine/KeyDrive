The map app: drive, walk or cycle — same trip, different method.

The Strategy pattern with a route planner: put each way of doing something in its own class and swap them.

❓ "What is the Strategy pattern and how does it relate to the Open/Closed Principle?"
👁 See it first
🎯 Put each way of doing something in its own small class behind one interface, and let the user of it choose which to plug in.
🌍 In real life

🗺️ A map app asks “how do you want to travel?”. The goal is the same (get there); the method differs: drive, walk or cycle. You can switch with one tap and the app itself is not rebuilt.

refactoring.guru: Strategy lets you define a family of algorithms, put each of them into a separate class, and make their objects interchangeable.

🔌 The fix: plug in a method

🧪 Tiny code
interface IRouteStrategy { int Minutes(int km); }
class Car  : IRouteStrategy { public int Minutes(int km) => km * 2; }
class Walk : IRouteStrategy { public int Minutes(int km) => km * 12; }
class Bike : IRouteStrategy { public int Minutes(int km) => km * 4; }

class RoutePlanner(IRouteStrategy strategy)
{
    public int Plan(int km) => strategy.Minutes(km);    // does not know which one
}

new RoutePlanner(new Car()).Plan(10);     // 20
new RoutePlanner(new Bike()).Plan(10);    // 40

This is the Open/Closed Principle in a named form — the IDiscount socket from the SOLID lab is a Strategy.

You write…It is…

Payment methods, tax rules, shipping rates, sortingthe usual business uses
🎯 Spot it: is the pattern a good fit?
▾ Several interchangeable ways to compute the same thing (pricing, tax, shipping)

✅ Good fit. Perfect: one class per way.

▾ One way, and it will never vary

❌ Overkill. Keep it simple.

▾ You choose the method at run time from user input

✅ Good fit. Strategy lets you swap it.

▾ A growing if/else on a “type” in many places

✅ Good fit. Replace with strategies.

👀 How to spot the need in your own code
If you see…Do this
if (mode == …) … else if … that grows with every new optionMake each option a strategy.
A class with several “flavour” flagsExtract each flavour into a strategy.
🔥 Interview recall
  • Strategy = interchangeable algorithms, each in its own class behind one interface.
  • The context uses the interface; callers choose the strategy.
  • It is Open/Closed in a named form.
  • Delegates and lambdas can act as lightweight strategies.
🎤 Say this in an interview
"The Strategy pattern puts each interchangeable way of doing something in its own class behind a common interface, and the context just uses the interface. Like a map app choosing drive, walk or cycle, adding a new option is a new class and the context never changes. It’s the Open/Closed Principle in a named form."
⚠️ Common trap

A strategy for something that never varies. Overkill.

Strategy vs State. Strategy is chosen from outside; State changes itself (next but one).
