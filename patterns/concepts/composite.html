Concept 9 of 24 · 🔧 Structural

Folders and files: treat a whole tree like a single thing.

The Composite pattern with folders and files: let single items and groups answer the same question so callers need no type checks.

❓ "What is the Composite pattern and where is it used?"
👁 See it first
🎯 Make single things and groups look the same, so one call works on both — and groups pass the call down to their children.
🌍 In real life

🗂️ On your computer you can right-click a file or a folder and choose “Properties”: you see a size either way. You do not think about whether it is one thing or a thousand.

refactoring.guru: Composite lets you compose objects into tree structures and then work with these structures as if they were individual objects.

🌳 The fix: both answer the same question
🎭 Who is who
Role in the patternIn our storyIn code
Component (common shape)“anything with a size”IItem.Size()

🧪 Tiny code
interface IItem { long Size(); }

class FileItem(long size) : IItem { public long Size() => size; }

class FolderItem : IItem
{
    private readonly List<IItem> _children = new();
    public void Add(IItem item) => _children.Add(item);
    public long Size() => _children.Sum(c => c.Size());      // asks children — files or folders
}

var root = new FolderItem();
root.Add(new FileItem(10)); root.Add(new FileItem(20));
var sub = new FolderItem(); sub.Add(new FileItem(5)); sub.Add(new FileItem(15));
root.Add(sub);
Console.WriteLine(root.Size());                              // 50

The caller only ever talks to IItem.

🔎 Where you already see it
You write…It is…
UI control trees (a panel contains buttons and other panels)a standard Composite example
Menus with sub-menus, org charts, file systemstree-shaped data
🎯 Spot it: is the pattern a good fit?
▾ Data that is naturally a tree: folders, menus, org chart

✅ Good fit. Composite lets callers treat leaf and group alike.

▾ A flat list of equal items

❌ Overkill. No tree; no pattern needed.

▾ You keep writing “if leaf … else loop children”

✅ Good fit. Move that into the types.

▾ Leaves and groups need totally different operations

❌ Overkill. A common interface will be awkward.

👀 How to spot the need in your own code
If you see…Do this
Type checks like is Folder before every operation on a treeGive both types the same method.
Recursion code repeated in many placesPut it inside the composite once.
🔥 Interview recall
  • Composite = leaves and groups share one interface; groups hold children and delegate.
  • Callers never check the kind.
  • Natural for trees: files, menus, UI, org charts.
  • Watch for operations that make no sense on leaves.
🎤 Say this in an interview
"Composite lets me treat individual objects and groups of objects uniformly. A file and a folder both implement the same interface; a folder implements it by asking its children. The caller can compute a whole tree’s size with one call and never checks types."
⚠️ Common trap

Forcing every operation onto leaves. Adding children to a file makes no sense.

Cycles. A folder containing itself recurses forever.
