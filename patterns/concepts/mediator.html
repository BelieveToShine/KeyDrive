The control tower: planes talk to the tower, not to each other.

The Mediator pattern: reduce tangled object-to-object links by routing them through one coordinator.

❓ "What is the Mediator pattern?"
👁 See it first
🎯 Let objects talk to one coordinator instead of to each other, so the tangle of links becomes a simple star.
🌍 In real life

🗼 Pilots do not phone each other. Everyone talks to air traffic control, which decides who goes first.

refactoring.guru: Mediator lets you reduce chaotic dependencies between objects by restricting direct communication and forcing them to collaborate via a mediator object.

🔧 The pattern fixes it
🧪 Tiny code
interface IMediator { void Send(string from, string message); }

class Tower : IMediator
{
    private readonly List<Plane> _planes = new();
    public void Register(Plane p) => _planes.Add(p);
    public void Send(string from, string msg) { foreach (var p in _planes.Where(p => p.Name != from)) p.Receive(msg); }
}
class Plane(string name, IMediator tower)
{
    public string Name => name;
    public void Say(string msg) => tower.Send(name, msg);        // talks to the tower only
    public void Receive(string msg) { }
}

In .NET, libraries such as MediatR use this idea for in-process messages (a third-party library).

🎯 Spot it: is the pattern a good fit?
▾ Many components that all need to coordinate (a dialog with many controls)

✅ Good fit. A mediator keeps them from knowing each other.

▾ Two objects that talk to each other

❌ Overkill. Direct calls are simpler.

▾ The mediator is becoming a huge class that knows everything

❌ Overkill. That is the main risk: a “god object”.

▾ You want components reusable without each other

✅ Good fit. Mediator decouples them.

👀 How to spot the need in your own code
If you see…Do this
Objects holding references to many peersIntroduce a coordinator.
🔥 Interview recall
  • Mediator = one coordinator; objects talk only to it.
  • Turns many-to-many into one-to-many.
  • Risk: the mediator becomes a god class.
🎤 Say this in an interview
"Mediator replaces a web of object-to-object calls with one coordinator, like a control tower, so components no longer know each other and the links grow linearly. The risk is a mediator that becomes a god object."
⚠️ Common trap

The all-knowing mediator. Keep it small.
