The hotel concierge: one easy front door to a messy system.

The Facade pattern with a hotel concierge: give callers one simple method instead of making them learn many subsystems.

❓ "What is the Facade pattern and when would you use it?"
👁 See it first
🎯 Hide a complicated set of pieces behind one simple, easy-to-use entry point.
🌍 In real life

🏨 A hotel concierge takes one request — “plan my evening” — and does the phoning, booking and ticket-buying for you. You never learn how the taxi company works.

refactoring.guru: Facade provides a simplified (but limited) interface to a complex system of classes, a library or a framework.

🏨 The fix: a concierge

🧪 Tiny code
// BEFORE — the caller must know every subsystem
taxi.Call(address); booking.Reserve("19:30", 2); tickets.Buy("show", 2);

// AFTER — a facade with one simple method
class EveningPlanner(TaxiService taxi, BookingService booking, TicketService tickets)
{
    public void Plan(string address)
    {
        tickets.Buy("show", 2);
        booking.Reserve("19:30", 2);
        taxi.Call(address);
    }
}
new EveningPlanner(t, b, k).Plan("12 Main St");     // one call

A facade is deliberately limited: it offers the common jobs, and the subsystems remain available for special cases.

🔎 Where you already see it
You write…It is…
File.ReadAllText(path)one call hides opening, reading, decoding and closing a stream (a common example of a facade-style API)
A service class that coordinates several repositories and an email senderan application-level facade
🎯 Spot it: is the pattern a good fit?
▾ A caller must use five classes in the right order to do one common job

✅ Good fit. A facade gives that job one method.

▾ The subsystem has only one simple method already

❌ Overkill. A facade adds nothing.

▾ You want to hide a messy legacy library from the rest of the app

✅ Good fit. A facade is a good boundary.

▾ The facade slowly grows every feature of the subsystems

❌ Overkill. Then it becomes a “god class”. Keep it small and focused.

👀 How to spot the need in your own code
If you see…Do this
The same 4–5 calls repeated in several placesWrap them in one facade method.
Callers need to know the right order of many callsHide the sequence.
🔥 Interview recall
  • Facade = one simple interface in front of a complex subsystem.
  • It is limited on purpose: common jobs only.
  • Subsystems stay usable directly.
  • Facade simplifies; Adapter converts shapes.
🎤 Say this in an interview
"A Facade is one simple entry point in front of a complicated set of classes, like a hotel concierge. Callers make one call instead of learning several subsystems and their order. I keep it small so it doesn’t become a god class, and the subsystems stay available for unusual cases."
⚠️ Common trap

The facade that does everything. It becomes a god class.

Hiding the subsystems completely so advanced users are stuck.
