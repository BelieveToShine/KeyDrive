The tax inspector: one visitor, different work per building.

The Visitor pattern: put a new operation in a separate object that visits each class in a family.

❓ "What is the Visitor pattern and what is its main drawback?"
👁 See it first
🎯 Move a new operation out into a “visitor” that knows how to handle each kind of object, and let objects accept visitors.
🌍 In real life

🧑‍💼 A tax inspector visits a house, a shop and a factory. The inspector does different work in each, but the buildings did not have to learn how to be inspected.

refactoring.guru: Visitor lets you separate algorithms from the objects on which they operate.

🔧 The pattern fixes it
🧪 Tiny code
interface IVisitor { void Visit(House h); void Visit(Shop s); }
interface IBuilding { void Accept(IVisitor v); }

class House : IBuilding { public void Accept(IVisitor v) => v.Visit(this); }
class Shop  : IBuilding { public void Accept(IVisitor v) => v.Visit(this); }

class TaxInspector : IVisitor
{
    public void Visit(House h) => Console.WriteLine("house tax");
    public void Visit(Shop s)  => Console.WriteLine("shop tax");
}
foreach (IBuilding b in new IBuilding[] { new House(), new Shop() }) b.Accept(new TaxInspector());

Drawback: adding a new class to the family means updating every visitor. In modern C#, pattern matching with a switch often covers simple cases.

🎯 Spot it: is the pattern a good fit?
▾ A stable family of classes that keeps getting new operations

✅ Good fit. Visitor keeps the classes unchanged.

▾ The family of classes keeps getting new members

❌ Overkill. Every visitor must change.

▾ Only one or two operations

❌ Overkill. A method on the class is simpler.

▾ Operations that need different logic per type

✅ Good fit. One visit method per type.

👀 How to spot the need in your own code
If you see…Do this
The same “add another method to every class” edit again and againMove the operations into visitors.
🔥 Interview recall
  • Visitor = separate an operation from the classes it works on.
  • Double dispatch: Accept calls the right Visit.
  • Easy to add operations; hard to add classes.
  • C# pattern matching is a lighter alternative.
🎤 Say this in an interview
"Visitor separates algorithms from the objects they operate on: classes expose Accept, and a visitor has a Visit method per type, so adding a new operation means adding a visitor rather than editing every class. The trade-off is that adding a new class forces changes to every visitor."
⚠️ Common trap

Wrong direction of change. Visitor suits stable classes with changing operations.
