The vine around the old tree: replace it one branch at a time.

The Strangler Fig pattern: migrate a legacy system gradually behind a routing front door, so users never see a big-bang switch.

❓ "What is the Strangler Fig pattern and why is it safer than a rewrite?"
👁 See it first
🎯 Put a routing front door in front of the old system, move one feature at a time to a new one, and switch the old one off when it is empty.
🌍 In real life

🌿 A strangler fig vine grows around a tree branch by branch. In time the vine is a complete tree of its own, and the old tree inside is gone — while the whole thing stood up the entire time.

The Azure Architecture Center describes Strangler Fig as migrating a legacy system incrementally behind a facade, so customers keep using the same interface and are unaware a migration is in progress.

🌿 The fix: grow around it
🎭 Who is who
Role in the patternIn our storyIn code

🧪 Tiny code
// A tiny routing rule: move features one at a time by changing this list
static readonly HashSet<string> MovedToNew = new() { "/search" };      // later add "/checkout", …

IResult Route(string path) =>
    MovedToNew.Any(p => path.StartsWith(p))
        ? Results.Redirect("https://new.shop.example" + path)     // new system
        : Results.Redirect("https://old.shop.example" + path);    // old system

Real setups use an API gateway or reverse proxy (for example YARP in .NET) with routing rules; the idea is the same.

🎯 Spot it: is the pattern a good fit?
▾ A large legacy system you cannot stop or freeze

✅ Good fit. Migrate in slices behind a router.

▾ A small app that can be rewritten in a week

❌ Overkill. Just rewrite it.

▾ The old and new must share a database for a while

✅ Good fit. Common: plan the data migration carefully.

▾ You can’t put anything in front of the old system

❌ Overkill. No front door, no strangler. Look for another seam.

👀 How to spot the need in your own code
If you see…Do this
A rewrite plan measured in years with one launch dateSlice it and ship value earlier.
“We can’t touch it” legacy codeWrap and replace slice by slice.
🔥 Interview recall
  • Strangler Fig = migrate gradually behind a facade/router; old and new run side by side.
  • Move one feature at a time; roll back by changing the route.
  • Users keep using the same interface.
  • Remove the old system when it is empty.
🎤 Say this in an interview
"The Strangler Fig pattern migrates a legacy system incrementally: I put a routing facade in front, move one feature at a time to the new implementation, keep the old one running for everything else, and retire it when it’s empty. It avoids a risky big-bang rewrite and delivers value continuously."
⚠️ Common trap

Never finishing. The old system lingers forever; set an end date.

Shared data headaches. Plan data ownership early.
