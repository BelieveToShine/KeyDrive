Deep dive · React lab · 🧰 Custom hooks

Reuse logic, not state.

What a custom hook is, why two components do not share its state, how to extract one, and the rules that keep it safe.

❓ "What is a custom hook and when should you write one?"
👁 See it first
🎯 A custom hook is a function named useSomething that lets you reuse stateful logic — not state — and keeps components readable.
▶️ Watch it happen: share logic, not state
📖 Why did this need to exist?

After the hooks guide you know the built-in tools. In a real app the same combination — a state variable, an effect, a cleanup — appears again and again: online status, debounced values, window size, local storage.

Copying that code into every component is noisy and easy to get wrong (a forgotten cleanup in one copy). A custom hook gives the combination a name and one home.

Custom hooks are also where the Rules of Hooks matter most, because the linter treats any function named use… as a hook.

🧪 Custom hook lab · the callback that reconnects
// A custom hook that takes a callback from the caller.
// If onMessage is a dependency, the effect reconnects whenever the parent passes a new function.
function useChatRoom({ roomId, onMessage }) {
  const onMsg = useEffectEvent(onMessage);          // an “event” the effect can call without depending on it
  useEffect(() => {
    const conn = connect(roomId);
    conn.on('message', onMsg);
    return () => conn.disconnect();
  }, [roomId]);                                          // reconnects only when the room changes
}

Illustrative. The docs use useEffectEvent for exactly this: wrapping an event-style callback so changing the callback does not force the effect to reconnect.

Why the name matters. The use prefix is a convention the linter relies on to apply the Rules of Hooks inside the function.

useEffectEvent is documented for wrapping callbacks that an effect should call but not depend on; check the docs for your React version’s status before relying on it.

Not for components. If the shared piece is UI, write a component; if it is logic with state or effects, write a hook.

🔥 Interview recall
  • A custom hook is a function whose name starts with use and that calls other hooks.
  • It shares logic, not state: each call is independent.
  • Do not use the use prefix if the function calls no hooks.
  • The Rules of Hooks apply inside custom hooks.
  • Extract when the same state + effect pattern repeats or a component gets hard to read.
  • To share state between components, lift it up or use context.
🎤 Say this in an interview
"A custom hook packages stateful logic — state plus effects plus cleanup — under a use-name so components stay readable and the logic is reused. Each call is independent, so it shares logic, not state; when state has to be shared I lift it up or use context. The Rules of Hooks apply inside it."
⚠️ Common trap

Expecting two components to share state through a hook. They each get their own.

A use… function that calls no hooks. It lies to readers and to the linter.
