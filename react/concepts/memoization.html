❓ "When should you use memo, useMemo and useCallback — and why does memo sometimes do nothing?"
👁 See it first
🎯 Memoization means “if the inputs are the same, reuse the last result.” It only helps when the inputs really stay the same — and only for work that was worth skipping.
▶️ Watch it happen: reuse when inputs match
📖 Why did this need to exist?

Page 5 found the biggest wrong thing: 500 ProductCards render again after every keystroke, with exactly the same props. Rendering them again produces the same output; the work is wasted.

React gives you tools to say “skip this when nothing changed”: memo for a whole component, useMemo for a calculated value, useCallback for a function. They have a price — comparisons and code — so they belong where a profile shows a real cost.

The React Compiler can add this memoization for you at build time. Even then, you need to understand it, because the profile still decides what is worth fixing.

🧰 Four tools, one idea
📋 Which one when?
ToolWhat it cachesUse it when
memo(Component)The rendered output, until a prop changesA profile shows a component re-rendering often with the same props, and the render is not trivial
useMemo(() => calc, [deps])The result of a calculationThe calculation is noticeably slow and its dependencies rarely change; or you need a stable object for a memoized child
useCallback(fn, [deps])The function itself (the same reference)You pass a function to a memoized child
React CompilerComponents and hooks, automaticallyYou want memoization without hand-writing it; it only memoizes components and hooks, and skips code that breaks the Rules of React

Memoization is a performance optimisation, not a guarantee. Your code must still be correct without it — React may still re-render a memoized component, and a memoized component still re-renders when its own state or a context it reads changes.

🧪 Memoization lab · from 504 renders to 4

ShopUI, one keystroke. Three attempts, each measured in the Profiler (illustrative numbers).

// Attempt 1 — memo, but a new function is created for every card on every render
const ProductCard = memo(ProductCardImpl);
products.map(p => <ProductCard key={p.id} product={p} onAdd={() => addToCart(p.id)} />)

// Attempt 2 — stable props: one function, the card passes its own id back
const addToCart = useCallback(id => dispatch({ type: 'add', id }), []);
products.map(p => <ProductCard key={p.id} product={p} onAdd={addToCart} />)

Illustrative sketch. In attempt 2, ProductCard calls onAdd(product.id) itself.

🧪 useMemo lab · only when it pays
const visible = useMemo(
  () => products.filter(p => p.name.includes(query)).sort(byPrice),
  [products, query]
);

Illustrative. This helps when other state changes (for example the cart drawer opens) and the list must not be recalculated. When query itself changes it recalculates anyway — so profile before adding it.

▾ Go one level deeper (60 seconds)

How the comparison works. memo compares each prop with Object.is. Two equal-looking objects are not equal unless they are the same object.

The React Compiler is a build-time tool that automatically memoizes components and values, mainly to reduce re-renders and expensive calculations. It checks code against the Rules of React and skips components that break them; its stable release is version 1.0. If you already wrote manual memoization, the docs say it keeps working alongside the compiler.

Profile first. Most calculations are fast, so the docs advise using useMemo for noticeably slow ones with rarely-changing dependencies.

🔥 Interview recall
  • Memoization = reuse the last result when the inputs are the same.
  • memo skips a render when all props are equal (Object.is).
  • Inline objects, arrays and functions are new every render and defeat memo.
  • useMemo caches a value; useCallback keeps one function.
  • The React Compiler adds memoization at build time; it does not replace profiling.
  • Memoization is an optimisation, not a guarantee — the code must be correct without it.
🎤 Say this in an interview
"I find the expensive re-render in the Profiler, then skip it with memo, making sure the props are stable — useCallback for functions, useMemo for objects or slow calculations. Inline objects and functions defeat memo, and memoization is only an optimisation, so I re-profile to prove it helped. The React Compiler can add much of this at build time."
⚠️ Common trap

memo with an inline function prop. The comparison fails every time; you pay for the check and still render.

Wrapping everything in useMemo/useCallback. Code gets noisy and slower to read; the profile never asked for it.

🧠 memo

Skips rendering a whole component when props are equal.

vs.
🧮 useMemo

Reuses the result of a calculation inside a component that is rendering anyway.
