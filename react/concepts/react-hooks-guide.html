📖 Why did this need to exist?

Pages 1–11 introduced hooks one at a time, where the story needed them. But when you open a real codebase you meet all of them at once, and the everyday question becomes: “I need to do X — which hook?”.

This page is the reference for that question: what every built-in hook does, whether it triggers a render, when to use it, and the mistake people usually make with it. It also shows the two Rules of Hooks, which the linter enforces for you.

Use it next to pages 2 (state), 4 (effects), 6 (memoization), 8 (context) and 9 (Suspense and transitions), which explain the behaviour in depth.

▾ Go one level deeper (60 seconds)

Why order matters. React keeps each component’s hook state in a list, so the same hooks must run in the same order on every render; that is what the rules protect.

Custom hooks are ordinary functions whose name starts with use and that call other hooks; they share logic, not state (see the custom hooks deep dive).

Library helpers. useSyncExternalStore was added mainly for libraries; application code rarely needs it directly.

🔥 Interview recall
  • State (and reducers) for values the screen shows; refs for values it does not; context for sharing; effects for syncing with outside.
  • Setting state re-renders; changing ref.current does not.
  • Never read or write a ref during render; use handlers or effects.
  • useMemo/useCallback/memo are optimisations — profile first.
  • Hooks run at the top level, in the same order every render; no hooks in conditions, loops, nested functions or try blocks.
  • useId is for accessibility ids, never list keys; useLayoutEffect runs before paint and can block it.
🎤 Say this in an interview
"I choose a hook by the question it answers: state when the screen shows the value, a ref when I must remember something without rendering, context to share, an effect to sync with the outside, and memoization only after a profile. I follow the Rules of Hooks — top level, same order — and rely on the lint rule to catch mistakes."
⚠️ Common trap

Storing displayed values in a ref. The screen will not update.

Calling a hook conditionally. It works until the condition flips, then React throws or mixes up state.

📸 useState

Remembers a value and re-renders when it changes.

vs.
📦 useRef

Remembers a value (or a DOM node) and stays silent when it changes.
