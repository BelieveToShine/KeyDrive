Concept 1 of 12 · 🧱 The problem

Why does one small change break far-away things?

Tangled code, in pictures: how a change ripples, and the five SOLID habits that stop it.

❓ "What is SOLID and why do we need it?"
👁 See it first
🎯 Good design means a small change touches one small place. SOLID is five habits that make that true.
🌍 In real life

🎧 Think of earphones in a bag. If the cable is tangled, pulling one end tugs everything else. If each cable is wound neatly, you can pull one out without touching the rest.

Code is the same. Pieces that know too much about each other get “tangled”. SOLID is the set of habits for keeping them neat.

🧹 The tidy version
🗺️ The five habits (one page each)
LetterThe habit in plain wordsPicture
S · Single ResponsibilityEach class does one job.🍽️ a restaurant with a chef, a waiter and a cashier
O · Open / ClosedAdd new things without editing old code.🔌 a power strip
L · Liskov SubstitutionA child class must keep its parent’s promises.🐧 a bird that cannot fly
I · Interface SegregationKeep interfaces small and focused.🖨️ a plain printer, not an all-in-one
D · Dependency InversionDepend on a socket, not on one particular bulb.💡 a light switch
🧭 Words you will meet
WordPlain meaning
Classa blueprint for objects (a piece of the program)
Interfacea list of promises: “anything of this kind can do these things”
Dependencysomething a class needs in order to work
Couplinghow tightly two pieces are tied together (tight = tangled)
Refactoringtidying code without changing what it does
🔥 Interview recall
  • Code “rots” when pieces are tangled: one change ripples into many places.
  • Good design: a change touches one small place.
  • SOLID = five habits: S, O, L, I, D — each prevents a different kind of tangle.
  • SOLID is a set of tools to use when there is pain, not a score to maximise.
🎤 Say this in an interview
"Code gets expensive to change when its pieces are tightly coupled, so one edit ripples through many places. SOLID is five design habits — single responsibility, open/closed, Liskov substitution, interface segregation and dependency inversion — that keep pieces small, replaceable and independent, so a change stays in one place."
⚠️ Common trap

“SOLID means more classes and more interfaces.” It means the right pieces, only where change really happens. Page 11 shows when to stop.
