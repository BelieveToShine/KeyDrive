📖 Why did this need to exist?

The Storage page said S3 is your default for files. Real buckets grow for years, and most of what is in them stops being read. Paying "hot" prices for cold data is the most common S3 waste. And a bucket that is too open is the most common S3 leak.

So S3 comes with levers: storage classes and lifecycle rules for cost, versioning for mistakes, presigned URLs for sharing, and Block Public Access for safety.

🧰 The levers

🔥 Standard and Intelligent-Tiering

the hot end✅ Pick it when
  • Standard: data accessed frequently, millisecond reads
  • Intelligent-Tiering: unknown or changing access; it moves objects between tiers and charges a small monitoring fee per object
⛔ Look elsewhere when
  • Very small objects in Intelligent-Tiering — those below a minimum size are not monitored

🧊 Infrequent Access classes

the middle✅ Pick it when
  • Data you read rarely but need instantly
  • One Zone-IA costs less but keeps data in a single zone
⛔ Look elsewhere when
  • One Zone-IA for data you cannot lose to a zone-level disaster

🏔️ Glacier classes

archives✅ Pick it when
  • Instant Retrieval: archives you still read in milliseconds
  • Flexible Retrieval: archive data read about once a year, minutes to hours
  • Deep Archive: read less than once a year, hours to restore
⛔ Look elsewhere when
  • Anything you may need right now — archived objects may need a restore first

⏳ Lifecycle rules

automatic transitions and expiry✅ Pick it when
  • Move objects to another class as they age
  • Expire objects (and old versions) you no longer need
  • Essential once versioning is on
⛔ Look elsewhere when
  • Forgetting minimum storage durations — early deletes can still be billed

▾ Go one level deeper (60 seconds) — details that cost money or data

Durability design. AWS publishes a very high durability design for the main classes — but durability does not protect against deletion by an authorized user or process. Versioning and Object Lock cover that gap.

Minimum durations. Some archive classes have minimum storage durations (for example, Glacier Instant Retrieval 90 days and Deep Archive 180 days). Deleting earlier can still be billed for the minimum.

Versioning without lifecycle can lead to unbounded storage growth, because every modification creates a new version that is kept indefinitely.

Presigned URLs are generated with the SDK or CLI, can grant GET or PUT, and are valid up to a maximum of seven days. They can be used many times until they expire.

Block Public Access. Buckets created since April 2023 block all public access by default. AWS recommends keeping all four settings on unless you know you need otherwise. A presigned URL does not require turning it off.

🔥 Interview recall
  • S3 classes trade storage price against access speed and retrieval cost: Standard → Intelligent-Tiering → Infrequent Access → Glacier → Deep Archive.
  • Lifecycle rules transition and expire objects; essential with versioning.
  • Presigned URL: a time-limited signed link; the bucket stays private; anyone with the link can use it until expiry.
  • Block Public Access on; least-privilege IAM and bucket policies; versioning for mistakes.
  • High durability ≠ protection from deletion.
🎤 Say this in an interview
"I match each S3 object to a storage class by how often it is read and let lifecycle rules move data as it ages — Intelligent-Tiering when the pattern is unknown. Buckets stay private with Block Public Access on and least-privilege policies; I share single objects with short-lived presigned URLs, and I turn on versioning with lifecycle for old versions so mistakes are recoverable."
⚠️ Common trap

Turning on versioning and forgetting lifecycle rules. Every overwrite keeps a new version forever, and the bill grows quietly.

Second trap: making a bucket public to share one file. A presigned URL does the job with a time limit and without opening everything.
